* 1. Visão Geral

** Objetivo
Migrar o ambiente Emacs de Doom (pesado, com Evil, gerência própria de
módulos/pacotes) para uma configuração *Vanilla modular*:

- Framework: *Emacs Bedrock* (=ashton314/emacs-bedrock=, Codeberg) — minimalista,
  =use-package= nativo (Emacs 29+), sem dependências ocultas.
- Sem =evil-mode=: keybindings 100% nativos.
- IA unificada: apenas =gptel= + =gptel-agent= conectados ao OpenCode Zen
  (descartando opencode.el, gemini-cli.el, macher, aider e afins no Emacs).
- 42 School preservada: =header42.el= e =flycheck-norminette.el= portados.

** Não-objetivos (nesta fase)
- Não reescrever a config do zero em uma sessão: o plano é por fases com o
  Doom rodando em paralelo (seção 5).
- Não migrar fluxos que dependem de Evil (ex.: =evil-window-*=, ophints).
- Não decidir definitivamente por =flycheck= vs =flymake=: recomendação abaixo
  (flycheck para preservar =flycheck-norminette.el= intacto).

    org — =custom-org.el= faz =require 'org= + =require 'ob-jupyter= antes do
    =add-to-list org-babel-load-languages=.
  - =vterm=: módulo C já compilado (=vterm-module.so=); o aviso só ocorre em
    =--batch= (Emacs desabilita módulos dinâmicos em batch — comportamento normal).

** Débitos técnicos herdados
1. 🐛 *Bug do advice* (=SPC o i p a= → "Wrong number of arguments"): o
   =advice-add :before= em =gptel-agent= recebe os 2 args da função original,
   mas a função de advice espera 0. A reescrita Vanilla *elimina o advice*.
   (Ver =todo.org= para o diagnóstico completo.)
2. Cadeia de checkers lsp→norminette com =lsp-managed-mode-hook=: no Vanilla
   só existe o chain =eglot→c-norminette=.
3. Dependência de =doom-project-root= em 3 funções: no Vanilla usar
   =(project-root (project-current))= (nativo) ou =default-directory=.

* 4. Nova Arquitetura Vanilla (Emacs Bedrock)  :docs:

** Princípios
1. *Só o que se usa*: cada =use-package= declara dependência e config juntas.
2. *Nativo primeiro*: eglot (não lsp-mode), treesit (com treesit-auto),
   =use-package= (não straight).
3. *Zero Evil*: keybindings nativos com prefixo =C-c=, navegação por
   =windmove=, seleção nativa.
4. *Declarativo no Nix*: todo binário de sistema vem do Home Manager; o repo
   Emacs não instala nada fora do MELPA/ELPA.
5. *Reprodutível e rastreável*: arquivos pequenos por domínio, versionados,
   com =custom-file= separado.

*** =+carlos/gptel-agent-run= — reescrita sem o bug de advice  :ia:
:CUSTOM_ID: reescrita-run
#+begin_src emacs-lisp
(defvar +carlos/gptel-agent-backend "Zen Claude"
  "Backend padrão para sessões de agente.")

(defvar +carlos/gptel-agent-model 'claude-sonnet-5
  "Modelo padrão para sessões de agente.")

(defun +carlos/gptel-agent-add-project-dirs ()
  "Adiciona `.agents/gptel/' do projeto atual a `gptel-agent-dirs'.
Sem advice: chamada direta antes de iniciar o agente."
  (when-let* ((proj (project-current))
              (root (project-root proj))
              (dir (expand-file-name ".agents/gptel/" root))
              (file-directory-p dir))
    (add-to-list 'gptel-agent-dirs dir)))

(defun +carlos/gptel-agent-run (&optional task)
  "Inicia uma sessão gptel-agent com TASK no buffer.
Usa a raiz do projeto; resolve o bug do advice anterior chamando
`+carlos/gptel-agent-add-project-dirs' diretamente."
  (interactive (list (read-string "🤖 Tarefa do agente: ")))
  (when (string-empty-p task)
    (user-error "Nenhuma tarefa especificada"))
  (+carlos/gptel-agent-add-project-dirs)     ; ← sem advice-add
  (let ((project-dir (or (project-root (project-current)) default-directory)))
    (gptel-agent project-dir 'gptel-agent)
    (when-let* ((buf (seq-find (lambda (b)
                                 (string-prefix-p "*gptel-agent:" (buffer-name b)))
                               (buffer-list))))
      (with-current-buffer buf
        (setq-local gptel-backend (gptel-get-backend +carlos/gptel-agent-backend))
        (setq-local gptel-model +carlos/gptel-agent-model)
        (goto-char (point-max))
        (insert task)
        (gptel-send)
        (message "🤖 Agente iniciado — %s" task)))))
#+end_src

** Mecanismo de coexistência (referência)  :docs:
O Emacs 29+ suporta =--init-directory= (internamente define =EMACSDIR= e
=user-emacs-directory=). Com isso:

- *Doom* continua intacto em =~/.config/emacs= (binários + =~/.config/doom=),
  versionado em =doom-emacs.git=.
- *Vanilla* vive em =~/.config/emacs-vanilla= (clone de
  =MyEmacs.git=) e é lançado com:

#+begin_src shell
emacs --init-directory "$HOME/.config/emacs-vanilla"
#+end_src

Isso isola pacotes, custom-file e cache: nenhuma interferência mútua.

** Integração Nix (dois acessos declarativos)  :docs:nix:
1. *Wrapper Home Manager* (=writeShellScriptBin=) no =emacs.nix=:

#+begin_src nix
(pkgs.writeShellScriptBin "emacs-vanilla" ''
  exec ${pkgs.emacs-pgtk}/bin/emacs --init-directory "$HOME/.config/emacs-vanilla" "$@"
'')
#+end_src

2. *Ativação*: manter o clone do Doom atual até o cutoff; o novo Vanilla é
   clonado do =MyEmacs.git= pelo mesmo =home.activation= (ou via repo git
   versionado em =~/.config/emacs-vanilla=):

# no home.activation (após writeBoundary), clonando o Vanilla:
