* Overview

Denote is a simple note-taking application for Emacs that uses a
Zettelkasten-inspired approach with date-based filenames. It emphasizes plain
text files, predictable naming conventions, and interoperability with other
tools.

- Zettelkasten-style note taking with date-based filenames
- Plain text files with predictable naming patterns
- Keyword/tag system embedded in filenames
- Support for Org mode, Markdown, and plain text notes
- Linking between notes with backlinks
- Directory "silos" for separate note collections
- No database required - files are the data store

Filename pattern: =YYYYMMDD--title__keywords.ext=

#+begin_warning
Denote directory must exist before use. Create it manually or in your config.
#+end_warning

* Core Concepts

** Filename Convention

All Denote notes follow a predictable naming pattern:

#+begin_example
YYYYMMDD--title__keywords.ext
#+end_example

- =YYYYMMDD= - Date in ISO format (e.g., =20260805=)
- =title= - Slugified title (lowercase, spaces replaced with hyphens)
- =__= - Separator between title and keywords
- =keywords= - Comma-separated keywords (no spaces around commas)
- =.ext= - File extension (=org=, =md=, =txt=, etc.)

Examples:
- =20260805--learning-emacs-lisp.org= (no keywords)
- =20260805--gtd-methodology__productivity,emacs.org=
- =20260805--python-decorators__python,programming.md=

** Keyword Rules

- Keywords are separated by commas
- No spaces around commas
- Keywords are lowercased by default
- Special characters in keywords are removed
- The =__= separator is only present when keywords exist

** Front Matter

Denote supports front matter for structured metadata.

Org mode front matter example:
#+begin_example
#+title: Learning Emacs Lisp
#+date: [2026-08-05 Wed 14:30]
#+identifier: 20260805T143023
#+filetags: :emacs:learning:

* Notes
Your content here.
#+end_example

Markdown front matter example:
#+begin_example
---
title: "Learning Emacs Lisp"
date: 2026-08-05T14:30:23+00:00
tags: ["emacs", "learning"]
---

# Notes
Your content here.
#+end_example

* Note Creation Workflow

** Basic Note Creation

1. Run =M-x denote= (=C-c n n= with recommended binding)
2. Enter title when prompted
3. Select keywords (comma-separated) from completion
4. Choose template (if configured)
5. Note is created and opened in a new buffer

** Note with Date Prompt

1. Run =M-x denote-date= (=C-c n d= with recommended binding)
2. Select date from calendar (or type it)
3. Enter title and keywords
4. Note is created with the selected date in filename

** Available Prompts (=denote-prompts=)

| Prompt Value | Description                          |
|--------------+--------------------------------------|
| =title=      | Prompt for note title                |
| =keywords=   | Prompt for keywords/tags             |
| =template=   | Prompt for template selection         |
| =subdirectory=| Prompt for subdirectory             |
| =date=       | Prompt for date (denote-date only)    |

Customize which prompts appear:
#+begin_src elisp
;; Only ask for title and keywords (skip template)
(setq denote-prompts '(title keywords))

;; Ask for everything
(setq denote-prompts '(title keywords template subdirectory))
#+end_src

** Subdirectory Notes

Denote supports organizing notes in subdirectories within =denote-directory=.

#+begin_src elisp
;; Create note in subdirectory
M-x denote-subdirectory
;; Prompts for subdirectory name, then title/keywords

;; Or configure automatic subdirectory
(setq denote-prompts '(title keywords subdirectory))
#+end_src

* Note Linking and Backlinks

** Creating Links

Denote uses a link format that encodes the note's identifier:

Org mode link format:
#+begin_example
[[denote:20260805T143023][Note Title]]
#+end_example

Markdown link format:
#+begin_example
[Note Title](denote:20260805T143023)
#+end_example

Plain text link format:
#+begin_example
denote:20260805T143023
#+end_example

** Creating a Link

1. Place cursor where you want the link
2. Run =M-x denote-link= (=C-c n l= with recommended binding)
3. Select target note from completion
4. Link is inserted at point

** Viewing Backlinks

1. Open the note you want to see backlinks for
2. Run =M-x denote-backlinks= (=C-c n b= with recommended binding)
3. A buffer opens showing all notes that link to the current one
4. Click links to navigate to the source notes

** Link Dired

Open a Dired buffer containing only notes linked from the current note:

1. Run =M-x denote-link-dired= (=C-c n L= with recommended binding)
2. A Dired buffer opens with linked files
3. Useful for reviewing related notes

** Link Resolution

Denote link resolution works by:
1. Scanning all files in =denote-directory=
2. Parsing the =denote:ID= format
3. Matching IDs to filenames
4. Opening the matching file

#+begin_warning
=denote-link= requires both notes to exist. You cannot link to a note that
hasn't been created yet.
#+end_warning

* Denote Silos (Multiple Directories)

Denote silos allow you to maintain separate note collections in different
directories. The =denote-silo-extras= package does NOT exist as a MELPA
package - implement silo functionality locally.

** Custom Silo Implementation

#+begin_src elisp
(defvar +carlos/denote-silo-directories
  (list (expand-file-name "~/org/notes")
        (expand-file-name "~/org/work-notes")
        (expand-file-name "~/org/project-42"))
  "Extra note directories (silos).")

(defun +carlos/denote-silo-new (&optional dir)
  "Create note in silo DIR."
  (interactive
   (list (if current-prefix-arg
             (completing-read "Silo: " +carlos/denote-silo-directories)
           (car +carlos/denote-silo-directories))))
  (let ((denote-directory (expand-file-name dir)))
    (denote)))

(global-set-key (kbd "C-c n s") #'+carlos/denote-silo-new)
#+end_src

* Renaming Notes

** Manual Rename

1. Open the note to rename
2. Run =M-x denote-rename-file= (=C-c n r= with recommended binding)
3. Edit the filename in the rename buffer
4. Press =C-c C-c= to confirm

The rename buffer preserves the directory path and only lets you edit the
filename portion. Denote handles updating links to the renamed note.

** Rename Using Front Matter

If you edit the front matter title of a note, Denote can automatically rename
the file to match:

#+begin_src elisp
;; Enable automatic rename from front matter
(setq denote-rename-file-using-front-matter t)

;; Or manually trigger:
M-x denote-rename-file-using-front-matter
#+end_src

** Bulk Rename

Denote provides bulk rename capabilities through =denote-rename-file=:
- Rename a single note
- Rename multiple notes in Dired
- Rename based on front matter changes

* Pitfalls & Common Errors

** Pitfall 1: =denote-silo-extras= is NOT a package
- Cause: Searching for =denote-silo-extras= on MELPA returns nothing
- Fix: Implement silo functionality locally as shown in the Silos section
#+begin_src elisp
;; WRONG - this package doesn't exist
(use-package denote-silo-extras
  :ensure t)

;; CORRECT - implement locally
(defvar +carlos/denote-silo-directories
  (list (expand-file-name "~/org/notes")))

(defun +carlos/denote-silo-new (&optional dir)
  (interactive
   (list (if current-prefix-arg
             (completing-read "Silo: " +carlos/denote-silo-directories)
           (car +carlos/denote-silo-directories))))
  (let ((denote-directory (expand-file-name dir)))
    (denote)))
#+end_src

** Pitfall 2: Filename pattern requires =__= for keywords
- Cause: Keywords must be separated from title by double underscore
- Fix: Ensure filename follows =YYYYMMDD--title__keywords.ext= pattern
#+begin_example
;; CORRECT
20260805--emacs-tips__emacs,productivity.org

;; WRONG - single underscore
20260805--emacs-tips_emacs,productivity.org

;; WRONG - missing separator
20260805--emacs-tips,emacs,productivity.org
#+end_example

** Pitfall 3: =denote-directory= must exist before use
- Cause: Denote doesn't automatically create the directory
- Fix: Create the directory in your config or manually
#+begin_src elisp
;; CORRECT - ensure directory exists
(setq denote-directory (expand-file-name "~/org/notes"))
(unless (file-directory-p denote-directory)
  (make-directory denote-directory t))

;; WRONG - will error if directory doesn't exist
(setq denote-directory "~/org/notes")
#+end_src

** Pitfall 4: Keywords in filenames use comma without spaces
- Cause: Spaces around commas break keyword parsing
- Fix: Use comma-separated keywords without spaces
#+begin_example
;; CORRECT
20260805--my-note__emacs,lisp.org

;; WRONG - spaces break keyword parsing
20260805--my-note__emacs, lisp.org
20260805--my-note__emacs , lisp.org
#+end_example

** Pitfall 5: =denote-link= requires both notes to exist
- Cause: Links are resolved by scanning existing files
- Fix: Create the target note before linking to it
#+begin_src elisp
;; WRONG - linking to non-existent note
;; (no error at link time, but backlinks won't work)

;; CORRECT - create target first
;; 1. M-x denote (create target note)
;; 2. M-x denote-link (link to it from another note)
#+end_src

** Pitfall 6: Renaming breaks links if not done through Denote
- Cause: External renames don't update link references
- Fix: Always use =denote-rename-file= to rename notes
#+begin_src elisp
;; WRONG - using external rename
;; mv old-name.org new-name.org
;; (links to old-name still point nowhere)

;; CORRECT - use denote's rename
M-x denote-rename-file
;; or programmatically:
(denote-rename-file "/path/to/old-name.org" "new-filename.org")
#+end_src

** Pitfall 7: Mixed file types in same directory
- Cause: =denote-file-type= sets default but doesn't enforce
- Fix: Be consistent with file types, or use subdirectories per type
#+begin_src elisp
;; Strategy 1: Use one file type globally
(setq denote-file-type 'org-mode)

;; Strategy 2: Use subdirectories per type
;; ~/org/notes/org/  -> .org files
;; ~/org/notes/md/   -> .md files
;; Then use denote-subdirectory to choose
#+end_src

** Pitfall 8: Duplicate identifiers
- Cause: Two notes created at the exact same second get the same ID
- Fix: Denote handles this automatically by appending a counter
#+begin_example
20260805T143023--note-one.org
20260805T143023-1--note-two.org  ;; Denote appends counter
#+end_example

** Pitfall 9: Front matter format mismatch
- Cause: Editing front matter manually with wrong format
- Fix: Use the correct front matter format for your file type
#+begin_example
;; ORG mode front matter - CORRECT
#+title: My Note
#+date: [2026-08-05 Wed 14:30]
#+identifier: 20260805T143023

;; MARKDOWN front matter - CORRECT
---
title: "My Note"
date: 2026-08-05T14:30:23+00:00
---

;; WRONG - mixing formats
#+title: My Note
---
title: "My Note"
---
#+end_example

                         (expand-file-name (buffer-file-name)))

* Notes for RAG Context

This reference covers Denote with focus on practical usage patterns. Key points
for automated agents:

1. =denote-silo-extras= does NOT exist as a MELPA package - implement silo
   functionality locally with custom functions
2. Note filenames follow the pattern: =YYYYMMDD--title__keywords.ext=
3. =denote-directory= must exist or be created before use
4. Keywords in filenames use =__= separator from title and commas between keywords
   with NO spaces around commas
5. =denote-link= requires both notes to exist before linking
6. Always use =denote-rename-file= to rename notes (not external tools)
7. Links use the =denote:ID= format where ID comes from the filename timestamp
8. File types supported: =org-mode=, =markdown=, =plain=, =toml=, =yaml=
9. Front matter format differs by file type (org properties vs YAML)
10. Denote is file-based - no database, notes are plain text files
11. =denote-open-or-create= can find existing notes by title fuzzy match
