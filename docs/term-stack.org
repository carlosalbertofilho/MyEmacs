* Overview

The Emacs terminal stack provides integrated shell environments within the
editor. It offers complementary approaches:

- **Eat** — ANSI/TUI emulation inside Eshell (htop, ranger, lazygit work)
- **VTerm** — full terminal emulator via C module (libvterm)
- **Eshell** — pure Elisp shell with deep Emacs integration
- **Popper** — intelligent popup window management for terminals

These are not competing tools but complementary: Eat for TUIs inside Eshell,
VTerm for full terminal compatibility, Eshell for Emacs-native scripting,
and Popper for clean window management.

#+begin_warning
This reference covers terminal packages only. See =completion-stack.org=
for completion frameworks, and =package-management.org= for Elpaca setup.
#+end_warning

* Eat (Emulate A Terminal)

** Purpose

Eat adds full terminal emulation to Eshell. It solves Eshell's historical
limitation: inability to run interactive TUI programs (htop, ranger, lazygit)
without breaking the display.

With Eat, Eshell becomes a hybrid:
- **Emacs mode** (default): C-a, C-e, C-k work normally
- **Char mode**: keys go directly to the running program (auto-activates for TUIs)

** Features**
- Full ANSI graphics support (colors, escape sequences)
- TUI support: htop, ranger, lazygit, tmux, vim
- Mouse support in terminal applications
- Sixel image rendering (if Emacs compiled with image support)
- Clipboard integration
- Clear command works properly (clears buffer, not just scrolls)

** Configuration**

#+begin_src elisp
(use-package eat
  :ensure t
  :hook (eshell-mode . eat-eshell-mode)
  :config
  (setq eat-enable-mouse t             ;; Mouse support in TUIs
        eat-kill-buffer-on-exit t)     ;; Clean up on exit
  ;; Char-mode: commands that require interactive input
  (add-to-list 'eat-semi-char-non-semi-commands "just")
  (add-to-list 'eat-semi-char-non-semi-commands "opencode")
  (add-to-list 'eat-semi-char-non-semi-commands "agy"))

;; Toggle between Emacs mode and Char mode
(with-eval-after-load 'eshell
  (define-key eshell-mode-map (kbd "C-c C-q") #'eat-toggle-char-mode))
#+end_src

** Eat Modes

| Mode          | When                    | Behavior                                |
|---------------+-------------------------+-----------------------------------------|
| Emacs mode    | At prompt (default)     | C-a, C-e, C-k, C-w work as Emacs keys   |
| Char mode     | Running TUI (auto)      | All keys sent directly to program       |
| Toggle        | C-c C-q (manual)        | Switch between modes                    |

** Key Variables**

| Variable                          | Default | Recommended | Purpose                          |
|-----------------------------------+---------+-------------+----------------------------------|
| =eat-enable-mouse=                | =nil=   | =t=         | Mouse support in TUIs            |
| =eat-kill-buffer-on-exit=         | =nil=   | =t=         | Auto-kill buffer on program exit |
| =eat-semi-char-non-semi-commands= | =list=  | =+just=     | Commands that trigger char mode  |

* VTerm

** Purpose

VTerm is a terminal emulator for Emacs using a compiled C module (=vterm-module.so=)
based on libvterm. It provides near-native terminal behavior.

** Features**
- Interactive programs (vim, htop, ncdu)
- ANSI color codes and escape sequences
- Mouse events in terminal applications
- True color (24-bit) support
- Bracketed paste mode

** Configuration**

#+begin_src elisp
(use-package vterm
  :ensure t
  :catch t
  :config
  (setq vterm-keymap-exceptions
        (delete "C-c" (delete "C-u" (delete "C-g" vterm-keymap-exceptions))))
  (setq vterm-max-scrollback 100000
        vterm-copy-exclude-prompt t))
#+end_src

** Key Variables**

| Variable                        | Default | Recommended | Purpose                           |
|---------------------------------+---------+-------------+-----------------------------------|
| =vterm-keymap-exceptions=       | =list=  | =modified=  | Keys Emacs intercepts in vterm    |
| =vterm-max-scrollback=          | =1000=  | =100000=    | Maximum scrollback buffer lines   |
| =vterm-copy-exclude-prompt=     | =nil=   | =t=         | Exclude prompt when copying       |

** Compilation Requirements**

VTerm requires =vterm-module.so= compilation. Dependencies:
- =cmake=, =gcc= or =clang=, =libtool=
- macOS: =brew install cmake libtool pkg-config=

* VTerm Toggle

** Purpose

vterm-toggle provides IDE-style terminal drawer behavior. Press =C-`= to
open/close a vterm buffer at the bottom of the frame, automatically cd'd
to the current project root.

** Configuration**

#+begin_src elisp
(use-package vterm-toggle
  :ensure t
  :after vterm
  :bind
  (("C-`" . vterm-toggle))
  :config
  (setq vterm-toggle-fullscreen-p nil
        vterm-toggle-scope 'project    ;; Open in current project root
        vterm-toggle-reuse-existing t))
#+end_src

** Key Variables**

| Variable                      | Default | Recommended | Purpose                          |
|-------------------------------+---------+-------------+----------------------------------|
| =vterm-toggle-fullscreen-p=   | =t=     | =nil=       | Don't take full frame            |
| =vterm-toggle-scope=          | =project=| =project=   | Open in project root             |
| =vterm-toggle-reuse-existing= | =nil=   | =t=         | Reuse existing vterm buffer      |

* Eshell

** Purpose

Eshell is a shell implemented entirely in Emacs Lisp with deep Emacs
integration: Lisp expressions in commands, native file globbing, pipeline
support with Elisp functions.

** Configuration**

#+begin_src elisp
(use-package eshell
  :ensure nil
  :bind
  (("C-c e" . eshell))
  :config
  (setq eshell-buffer-name "*eshell*"
        eshell-scroll-to-bottom-on-input 'all
        eshell-error-if-no-glob t
        eshell-hist-file-size 10000
        eshell-cmpl-cycle-completions nil)
  ;; Sync PATH with system shell
  (setq eshell-path-extra
        (append '("/etc/profiles/per-user/carlosfilho/bin"
                  "/run/current-system/sw/bin"
                  "/nix/var/nix/profiles/default/bin")
                eshell-path-extra)))
#+end_src

** Key Variables**

| Variable                            | Default          | Purpose                          |
|-------------------------------------+------------------+----------------------------------|
| =eshell-buffer-name=                | ="*eshell*"=     | Name of eshell buffer            |
| =eshell-scroll-to-bottom-on-input=  | =nil=            | Auto-scroll on input             |
| =eshell-hist-file-size=             | =500=            | Number of history entries        |
| =eshell-path-extra=                 | =nil=            | Extra PATH entries               |

** Eshell vs VTerm vs Eat

| Feature                | Eshell + Eat              | VTerm                     | Eshell puro               |
|------------------------+---------------------------+---------------------------+---------------------------|
| Implementation         | Elisp + ANSI emulation    | C module (libvterm)       | Pure Elisp                |

| ANSI colors            | Full                      | 24-bit true color         | Basic                     |
| Emacs integration      | Deep                      | Moderate                  | Deep                      |
| Compilation required   | No                        | Yes                       | No                        |
| Best for               | Daily use + TUIs          | Heavy terminal sessions   | Quick Elisp commands      |

* CAPF Autosuggest

** Purpose

Provides Fish Shell / Zsh-autosuggestions style inline ghost text completions
in Eshell. As you type, it shows matching commands from history in gray text.
Press =→= or =End= to accept.

** Configuration**

#+begin_src elisp
(use-package capf-autosuggest
  :ensure t
  :hook (eshell-mode . capf-autosuggest-mode)
  :config
  (setq capf-autosuggest-look-back 1000)) ;; Search back in history
#+end_src

** Key Variables**

| Variable                          | Default | Purpose                           |
|-----------------------------------+---------+-----------------------------------|
| =capf-autosuggest-look-back=      | =500=   | Lines to search back in history   |

** Usage**

1. Type a command prefix (e.g., =git s=)
2. Ghost text appears: =git s=tatus=
3. Press =→= or =End= to accept
4. Press =C-g= to dismiss

* Popper (Window Management)

** Purpose

Popper classifies terminal buffers as "popups" — they appear in a dedicated
area, can be toggled with a single key, and don't mess up your editing layout.
Similar to Dirvish's sidebar behavior but for any buffer type.

** Configuration**

#+begin_src elisp
(use-package popper
  :ensure t
  :bind
  (("C-`"   . popper-toggle-latest)
   ("M-`"   . popper-cycle)
   ("C-M-`" . popper-toggle-type))
  :init
  (setq popper-reference-buffers
        '("\\*eshell\\*"
          "\\*vterm\\*"
          "\\*eat\\*"
          "\\*compilation\\*"
          "\\*async-shell-command\\*"
          output-mode
          help-mode))
  :config
  (popper-mode 1)
  (popper-echo-mode 1))  ;; Show popup info in echo area
#+end_src

** Key Bindings**

| Key       | Action                              |
|-----------+-------------------------------------|
| =C-`=     | Toggle latest popup                 |
| =M-`=     | Cycle through popups                |
| =C-M-`=   | Toggle popup type (side/bottom)     |

** Reference Buffers**

| Pattern                  | Matches                    |
|--------------------------+----------------------------|
| =\\*eshell\\*=           | Eshell buffers             |
| =\\*vterm\\*=            | VTerm buffers              |
| =\\*eat\\*=              | Eat buffers                |
| =\\*compilation\\*=      | Compilation output         |
| =output-mode=            | Async command output       |
| =help-mode=              | Help buffers               |

* Just + Eat Integration

** Purpose**

Run Justfile recipes directly from Emacs in an eat buffer, with:
- Project-aware execution (runs from project root)
- Interactive recipe selection via completing-read
- Full ANSI output and TUI support via eat

** Configuration**

#+begin_src elisp
(defun +carlos/project-just-run ()
  "Run the default just recipe in project root using eat."
  (interactive)
  (when-let* ((root (project-root (project-current t))))
    (let* ((buf-name (format "*just: %s*" (file-name-nondirectory (directory-file-name root))))
           (eat-buf (eat-make-buffer buf-name)))
      (with-current-buffer eat-buf
        (cd root)
        (eat-exec-cmd "just" nil))
      (pop-to-buffer eat-buf))))

(defun +carlos/eat-just-recipe (recipe)
  "Run a specific just RECIPE in project root using eat."
  (interactive
   (list (completing-read "Just recipe: "
                          (process-lines "just" "--summary"))))
  (when-let* ((root (project-root (project-current t))))
    (let* ((buf-name (format "*just: %s*" recipe))
           (eat-buf (eat-make-buffer buf-name)))
      (with-current-buffer eat-buf
        (cd root)
        (eat-exec-cmd "just" (list recipe)))
      (pop-to-buffer eat-buf))))

(global-set-key (kbd "C-c j j") #'+carlos/project-just-run)
(global-set-key (kbd "C-c j r") #'+carlos/eat-just-recipe)
#+end_src

** Project Switch Menu**

Added to =project-switch-commands=:
- =?j= — Run default just recipe
- =?t= — Select and run specific recipe

** How It Works**

1. =just --summary= reads all recipes from Justfile
2. =completing-read= shows menu (Vertico/Consult compatible)
3. Eat buffer opens in project root
4. Recipe runs with full ANSI/TUI support

* Pitfalls & Common Errors

** P1: VTerm C Module Compilation

- **Symptom:** =vterm= loads but displays "vterm-module not compiled" error
- **Cause:** =vterm-module.so= was not built during package installation
- **Fix:** Run =M-x vterm-install= or install deps: =brew install cmake libtool=
- **Severity:** High — vterm is non-functional without the module

** P2: Eshell PATH Missing Tools

- **Symptom:** =which opencode= returns nil in Eshell but works in system shell
- **Cause:** Eshell has isolated PATH that doesn't inherit from system
- **Fix:** Add paths to =eshell-path-extra=
- **Severity:** Medium — breaks AI tool aliases

** P3: Eat Char-Mode Not Activating

- **Symptom:** Interactive program (htop, just) breaks display in Eshell
- **Cause:** Command not in =eat-semi-char-non-semi-commands=
- **Fix:** Add command to list or toggle manually with =C-c C-q=
- **Severity:** Medium — TUIs don't render correctly

** P4: Eshell Git Prompt Regex Mismatch

- **Symptom:** History navigation (=M-p=, =M-n=) doesn't work
- **Cause:** =eshell-prompt-regexp= doesn't match prompt output
- **Fix:** =eshell-git-prompt= sets its own regexp — don't override
- **Severity:** Medium — breaks core eshell functionality

** P5: Popper Not Recognizing Buffers

- **Symptom:** Terminal buffers don't appear as popups
- **Cause:** Buffer name not in =popper-reference-buffers=
- **Fix:** Add pattern to list (use =\\*PATTERN\\*= format)
- **Severity:** Low — cosmetic, easy to debug

** P6: Just Recipe Menu Empty

- **Symptom:** =C-c j r= shows empty completion list
- **Cause:** No Justfile in project root, or =just= not installed
- **Fix:** Ensure Justfile exists and =just= is in PATH
- **Severity:** Low — only affects just integration

- =C-c C-q= toggles between Emacs mode and Char mode in eat
- Eshell has isolated PATH — use =eshell-path-extra= for system tools
- =eshell-git-prompt= replaces =eshell-prompt-extras= (don't use both)
- =popper= manages terminal buffers as popups — doesn't mess up layout
- Just integration uses =eat-make-buffer= + =eat-exec-cmd= for ANSI output
- AI tool aliases use explicit paths (Eshell PATH ≠ system PATH)
- =vterm-toggle= and =popper= both use =C-`= — popper takes precedence

** Choosing Between Eshell+Eat and VTerm**

- Use **Eshell + Eat** for: daily commands, TUIs (htop, ranger, lazygit),
  AI CLI tools (opencode, agy), Emacs integration (Lisp expressions,
  buffer redirection)
- Use **VTerm** for: heavy terminal sessions, full shell compatibility,
  when you need exact system terminal behavior
- Use **both**: Eshell+Eat for daily use, VTerm via =C-`= for when you
  need a real terminal
