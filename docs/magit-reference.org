* Overview

Magit is a complete Git porcelain interface for Emacs. It provides an intuitive
transient-based UI for all common Git operations and more. Magit is widely
considered one of the best Git interfaces available in any editor.

- Transient-based command menus (prefix keys with =C-u= for options)
- Full Git functionality accessible from =magit-status= buffer
- Interactive staging/unstaging with fine-grained control
- Branch visualization and management
- Bisecting, rebasing, cherry-picking, and more
- Integration with =vc-git= for version control indicators

* Installation

#+begin_src elisp
;; Install from MELPA
M-x package-install RET magit RET

;; Verify installation
M-x magit-status
#+end_src

#+begin_warning
Magit requires Transient >= 0.4.0. Ensure your Transient package is up to date.
#+end_warning

#+begin_src elisp
(use-package magit
  :ensure t
  :bind (("C-c g" . magit-status))
  :config
  (setq magit-display-buffer-function #'magit-display-buffer-same-window-except-diff-v1))
#+end_src

* Magit Status Buffer

The =magit-status= buffer is the central hub for all Git operations. Open it
with =M-x magit-status= from any buffer within a Git repository.

** Layout

The status buffer shows sections in this order:
1. *Header* - Repository path and branch info
2. *Untracked files* - Files not yet tracked by Git
3. *Unstaged changes* - Modified files not yet staged
4. *Staged changes* - Files staged for commit
5. *Unpushed/unpulled commits* - Remote tracking status
6. *Recent commits* - Last few commits on current branch

** Navigating Sections

| Key          | Action                                      |
|--------------+---------------------------------------------|
| =TAB=        | Toggle section visibility (expand/collapse)  |
| =S-TAB=      | Toggle all sections                          |
| =n= / =p=    | Next / previous section                      |
| =M-n= / =M-p=| Next / previous section (same level)         |
| =g=          | Refresh status buffer                        |
| =q=          | Quit Magit                                   |
| =C-c C-c=    | Finish current action (commit, etc.)         |

** Operating on Files

In the status buffer, point must be on a file line to operate on it:

| Key | Action                            |
|-----+-----------------------------------|
| =s= | Stage file or hunk under point    |
| =u= | Unstage file or hunk under point  |
| =k= | Discard changes in file or hunk   |
| =v= | Reverse (undo) a commit           |
| =d= | Show diff for file under point    |
| =S= | Stage all changes                 |
| =U= | Unstage all changes               |
| =K= | Discard all changes               |

* Commit Workflow

** Creating a Commit

1. Stage files with =s= in the status buffer
2. Press =c c= to create a commit
3. Enter commit message in the commit buffer
4. Press =C-c C-c= to finalize the commit

** Commit Buffer

The commit buffer provides:
- Commit message editing area
- Diff of staged changes at the bottom
- =C-c C-c= to commit
- =C-c C-k= to cancel
- =C-c C-a= to add Acked-by
- =C-c C-s= to add Signed-off-by

** Commit Variations

| Key     | Function                    | Description                     |
|---------+-----------------------------+---------------------------------|
| =c c=   | =magit-commit=              | Normal commit                   |
| =c a=   | =magit-commit-amend=        | Amend last commit               |
| =c e=   | =magit-commit-extend=       | Extend last commit (keep msg)   |
| =c f=   | =magit-commit-fixup=        | Create fixup commit             |
| =c s=   | =magit-commit-squash=       | Create squash commit            |
| =c A=   | =magit-commit-absorb=       | Absorb staged changes           |
| =c w=   | =magit-commit-reword=       | Reword last commit message      |

** Programmatic Commit

#+begin_src elisp
;; Get staged diff as string
(magit-git-string "diff" "--cached")

;; Get unstaged diff
(magit-git-string "diff")

;; Check if anything is staged

;; Returns nil if nothing staged, non-nil otherwise
#+end_src

* Integration with GPTel for Commit Messages

Use GPTel to generate commit messages from staged diffs.

** Setup (API do gptel 0.9.9.5)

O helper `+carlos/gptel-request` (definido em `custom-ai.el`) encapsula o padrão
correto: `gptel-request` NÃO aceita `:backend`/`:model` — o backend/modelo são
buffer-local. O commit real está em `lisp/custom-git.el`; o exemplo abaixo mostra
o padrão:

#+begin_src elisp
(defun +carlos/gptel-generate-commit-message ()
  "Generate commit message using IA from staged diff."
  (interactive)
  (unless (vc-git-root default-directory)
    (user-error "Not in a Git repository"))
  (let ((diff (shell-command-to-string "git diff --cached")))
    (if (string-empty-p diff)
        (user-error "Nothing staged for commit")
      (+carlos/gptel-request
       (format "Generate a concise commit message for this diff:\n\n%s" diff)
       "OpenCode Zen"
       'deepseek-v4-flash-free
       :system "You are an expert at writing conventional commits."
       :callback
       (lambda (response _info)
         (when response
           (let ((msg (string-trim response)))
             (kill-new msg)
             (message "Commit message: %s" msg))))))))
#+end_src

** Usage

1. Stage your changes in Magit (=s= on files/hunks)
2. Run =M-x +carlos/gptel-generate-commit-message=
3. The generated message is copied to the kill ring
4. Open the commit buffer (=c c=) and =C-y= to paste

** Alternative: Insert Directly into Commit Buffer

#+begin_src elisp
(defun +carlos/gptel-insert-commit-message ()
  "Generate and insert commit message into current commit buffer."
  (interactive)
  (unless (derived-mode-p 'git-commit-mode 'magit-commit-mode)
    (user-error "Not in a git commit buffer"))
  (let ((diff (shell-command-to-string "git diff --cached")))
    (if (string-empty-p diff)
        (user-error "Nothing staged for commit")
      (let ((commit-buf (current-buffer)))
        (+carlos/gptel-request
         (format "Generate a concise commit message for this diff:\n\n%s" diff)
         "OpenCode Zen"
         'deepseek-v4-flash-free
         :system "You are an expert at writing conventional commits."
         :callback
         (lambda (response _info)
           (when response
             (with-current-buffer commit-buf
               (goto-char (point-min))
               (insert (string-trim response))))))))))

;; Atalho dentro do buffer de commit
(add-hook 'git-commit-mode-hook
          (lambda ()
            (local-set-key (kbd "C-c C-g") #'+carlos/gptel-insert-commit-message)))
(with-eval-after-load 'magit
  (when (boundp 'magit-commit-mode-map)
    (define-key magit-commit-mode-map (kbd "C-c C-g")
      #'+carlos/gptel-insert-commit-message)))
#+end_src

#+begin_warning
=vc-git-root= and =shell-command-to-string= are the vanilla Emacs approach.
Do NOT use =magit-git-string= if Magit may not be loaded - it requires the
full Magit package to be initialized.
#+end_warning

* Pitfalls & Common Errors

** Pitfall 1: Magit in batch mode
- Cause: Magit requires a full Emacs instance with a display
- Fix: Do not use Magit in =--batch= mode. Use plain =git= commands instead
#+begin_src elisp
;; WRONG - will fail in batch mode
(magit-status)

;; CORRECT for batch/scripts
(shell-command-to-string "git status --porcelain")
#+end_src

** Pitfall 2: Not in a Git repository
- Cause: =magit-status= called outside a Git repo
- Fix: Ensure =default-directory= is within a Git repository
#+begin_src elisp
;; Check before calling magit
(when (vc-git-root default-directory)
  (magit-status))

;; Or let magit prompt for repo directory
(magit-status-setup-buffer "/path/to/repo")
#+end_src

** Pitfall 3: =magit-git-string= without Magit loaded
- Cause: =magit-git-string= is a Magit function, not available without loading Magit
- Fix: Use =shell-command-to-string= for vanilla Git access
#+begin_src elisp
;; WRONG (if magit not loaded)
(magit-git-string "diff" "--cached")

;; CORRECT (vanilla Emacs)
(shell-command-to-string "git diff --cached")
#+end_src

** Pitfall 4: Commit with nothing staged
- Cause: Attempting to commit when no files are staged
- Fix: Stage files first, or use =magit-commit-ask-to-stage=
#+begin_src elisp
;; Check if anything is staged
(let ((diff (shell-command-to-string "git diff --cached")))
  (if (string-empty-p diff)
      (message "Nothing staged")
    (message "Ready to commit")))
#+end_src

** Pitfall 5: Display buffer behavior
- Cause: Magit opens buffers in new windows by default
- Fix: Set display function for single-window behavior
#+begin_src elisp
;; Open Magit in same window (except diff buffers)
(setq magit-display-buffer-function
      #'magit-display-buffer-same-window-except-diff-v1)

;; Alternative: always use same window
(setq magit-display-buffer-function #'magit-display-buffer-traditional)
#+end_src

** Pitfall 6: Magit and =magit-auto-revert=
- Cause: Auto-revert can cause flickering in the status buffer
- Fix: Disable if causing issues, or set interval
#+begin_src elisp
;; Disable auto-revert if flickering occurs
(setq magit-auto-revert nil)

;; Or use a longer interval
(setq auto-revert-interval 5)
#+end_src

** Pitfall 7: Transient menu errors
- Cause: Outdated Transient package
- Fix: Update Transient to >= 0.4.0
#+begin_src elisp
;; Check Transient version
(package-version-identity (cadr (assq 'transient package-alist)))
#+end_src

** Pitfall 8: Performance with large repos
- Cause: Magit can be slow on very large repositories
- Fix: Use =--no-optional-locks= and limit log depth
#+begin_src elisp
;; Speed up Magit for large repos
(setq magit-git-global-arguments
      '("--no-optional-locks"
        "--literal-pathspecs"
        "--no-pager"))

;; Limit initial log display
(setq magit-log-auto-more nil)
#+end_src

  :ensure t
  :bind (("C-c g" . magit-status))
  :config
  ;; Display settings

        #'magit-display-buffer-same-window-except-diff-v1

        magit-diff-paint-whitespace t)

  ;; Section visibility
  (setq magit-section-initial-visibility-alist
        '((unpulled . show)
          (unpushed . show)
          (stashes . hide)
          (modules . hide)))

  ;; Git global arguments (performance)
  (setq magit-git-global-arguments
        '("--no-optional-locks"
          "--literal-pathspecs"
          "--no-pager")))

;; Optional: Magit with GPTel commit message generation
;; (API gptel 0.9.9.5: use o helper +carlos/gptel-request — sem :backend/:model)
(defun +carlos/gptel-insert-commit-message ()
  "Generate and insert commit message into current commit buffer."
  (interactive)
  (unless (derived-mode-p 'git-commit-mode 'magit-commit-mode)
    (user-error "Not in a git commit buffer"))
  (let ((diff (shell-command-to-string "git diff --cached")))
    (if (string-empty-p diff)
        (user-error "Nothing staged for commit")
      (let ((commit-buf (current-buffer)))
        (+carlos/gptel-request
         (format "Generate a concise commit message for this diff:\n\n%s" diff)
         "OpenCode Zen"
         'deepseek-v4-flash-free
         :system "You are an expert at writing conventional commits."
         :callback
         (lambda (response _info)
           (when response
             (let ((msg (string-trim response)))
               (with-current-buffer commit-buf
                 (goto-char (point-min))
                 (insert msg)))))))))

(add-hook 'git-commit-mode-hook
          (lambda ()
            (local-set-key (kbd "C-c C-g") #'+carlos/gptel-insert-commit-message)))
#+end_src

* Notes for RAG Context

This reference covers Magit with focus on practical usage patterns. Key points
for automated agents:

1. Magit requires a full Emacs instance - do not use in =--batch= mode
2. =magit-status= requires being in a Git repository (check with =vc-git-root=)
3. For commit message generation without Magit loaded, use =vc-git-root= and
   =(shell-command-to-string "git diff --cached")=
4. =magit-git-string= requires Magit - use =shell-command-to-string= for vanilla approach
5. Magit's display function controls buffer behavior - set it for preferred UX
6. Transient menus use prefix keys: =c=, =b=, =P=, =F=, =l=, =d=, =t=, =r=, =z=
7. =C-c C-c= finalizes actions in Magit buffers (commits, rebases, etc.)
8. =g= refreshes any Magit buffer; =q= quits
