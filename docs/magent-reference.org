* Smart-Edit — Editor Transacional (=custom-magent-tool-smart-edit.el=)

Infraestrutura de edição segura para todas as ações de smart-edit (org + 8 linguagens code).
Cada mutação é executada como uma *transação*: snapshot do buffer antes, execução do thunk,
validação de integridade (org-lint ou check-parens), e restauração byte-a-byte em caso de falha.

** +carlos/magent--smart-edit-transaction (buf kind thunk)
- *Tipo:* Função
- *Módulo:* =lisp/custom-magent-tool-smart-edit.el= (linha 36)
- *Parâmetros:*
  - =buf= — buffer alvo (file-backed para persistência)
  - =kind= — =\\='org= (org-lint gate), =\\='code= (check-parens gate), ou =\\='raw= (sem gate de domínio)
  - =thunk= — função sem argumentos que executa as mutações e devolve a mensagem de sucesso
- *Comportamento:*
  1. Snapshot via =buffer-substring-no-properties=
  2. Executa thunk, captura valor de retorno (=msg=)
  3. Gate de validação conforme kind (org-lint para .org, check-parens para código)
  4. =basic-save-buffer= para persistir
  5. Em erro: restore byte-a-byte do snapshot, save, retorna string de erro (nunca sinaliza)
- *Exemplo:* =(+carlos/magent--smart-edit-transaction buf \\='code (lambda () (goto-char (point-max)) (insert " x") "inserido"))=

** +carlos/magent--smart-edit-replace-core (old new &optional flags)
- *Tipo:* Função
- *Módulo:* =lisp/custom-magent-tool-smart-edit.el= (linha 63)
- *Parâmetros:*
  - =old= — texto literal a buscar
  - =new= — substituto
  - =flags= — =nil= ou ="ALL"= (literal global), ="FIRST"= (primeira ocorrência), ="WORD"= (fronteiras de símbolo via =\\_<...\\_>=), ="REGEX"= (padrão regex bruto)
- *Retorno:* contagem de substituições (inteiro)
- *Nota:* =search-forward= já é literal por padrão; =WORD= e =REGEX= são as únicas formas que usam regexp.

** Regra de ouro: primitive-undo removido
Nenhuma variante usa mais =primitive-undo= (API de undo-list, não buffer — rollback
anterior era fictício). Todas as mutações passam pelo helper transacional que garante
rollback byte-a-byte via snapshot/restore. Meta-teste ERT
=myemacs-smart-edit-no-primitive-undo= valida que =primitive-undo= não reaparece.

* DevOps Tools (=custom-magent-tool-devops.el= / =custom-magent-tool-git.el=)

Ferramentas nativas para operações destrutivas em Docker, Systemd e Git.
Todas seguem o padrão *dry_run* para preview seguro antes da execução.

** Padrão dry_run (operação destrutiva)

Três tools destrutivas aceitam o parâmetro =dry_run= (string "true"):

| Tool                  | Ações destrutivas          | Fonte                              |
|-----------------------|----------------------------|-------------------------------------|
| =docker_action=       | =remove=, =rm=, =stop=     | =custom-magent-tool-devops.el=     |
| =systemd_action=      | =stop=, =disable=          | =custom-magent-tool-devops.el=     |
| =magit_branch_delete= | (todas as deleções)        | =custom-magent-tool-git.el=        |

*Comportamento:*

1. Se =dry_run= não é ="true"= → executa normalmente.
2. Se =dry_run= é ="true"= → retorna JSON com:
   - =status= = ="dry_run"=
   - =destructive= = =t= ou =nil= (se ação é destrutiva)
   - =command= → comando que seria executado
   - =message= → descrição legível

*Exemplo de resposta dry_run:*
#+begin_src json
{"status": "dry_run", "destructive": true, "command": "docker rm 'web'", "container": "web", "action": "remove", "message": "Would remove container 'web'."}
#+end_src

*Nota:* o parâmetro =dry_run= usa =string= (não =boolean=) porque o gptel serializa tudo como JSON string. A comparação interna é =(equal dry-run "true")=.

** docker_action (=+carlos/magent-tool-docker-action=)

Ações de lifecycle em containers Docker (local ou TRAMP).

- *Parâmetros:*
  - =container_id= -- nome ou ID do container
  - =action= -- =start=, =stop=, =restart=, =remove=
  - =remote_host= -- prefixo TRAMP opcional (ex: =/ssh:admin@host:=)
  - =dry_run= -- ="true"= para preview sem executar
  - =reason= -- justificativa (display-only)

** systemd_action (=+carlos/magent-tool-systemd-action=)

Gerenciamento de units systemd (local ou TRAMP).

- *Parâmetros:*
  - =unit= -- nome da unit (ex: =nginx.service=, =docker=)
  - =action= -- =start=, =stop=, =restart=, =reload=, =enable=, =disable=
  - =remote_host= -- prefixo TRAMP opcional
  - =dry_run= -- ="true"= para preview sem executar
  - =reason= -- justificativa (display-only)

** magit_branch_delete (=+carlos/magent-tool-magit-branch-delete=)

Exclui branches locais ou remotas via Magit API.

- *Parâmetros:*
  - =branch= -- nome da branch alvo
  - =remote= -- nome do remote (ex: =origin=) ou ="true"= para remota
  - =force= -- ="true"= para force delete (-D)
  - =dry_run= -- ="true"= para preview sem executar
  - =reason= -- justificativa (display-only)

*Nota:* esta tool requer =magit= carregado. Em batch sem magit, retorna erro informativo.


* Criação e Registro de Ferramentas (Tool Registration)

As ferramentas externas do ecossistema Magent devem, obrigatoriamente, ser estruturadas usando ~gptel-make-tool~. Versões antigas anexavam plists cruas diretamente à lista ~gptel-tools~, o que causava crash (~Wrong type argument: gptel-tool~) nas engines mais recentes do gptel/magent.

**Padrão de Implementação (Fase D)**

Para adicionar uma nova ferramenta (ex: ~lisp/custom-magent-tool-test.el~):

1. *Struct Gptel:* Use ~gptel-make-tool~ com chaves estritas (~:name~, ~:description~, ~:function~, ~:category~).
2. *Args Tipados:* O argumento ~:args~ deve ser uma plist de plists no formato
   ~((:name "arg1" :type string :description "..."))~ (o ~:type~ é um *símbolo*:
   ~string~, ~number~, ~integer~, ~boolean~, ~array~, ~object~, ~null~).
3. *Roteamento Magent:* A struct gerada deve ser registrada em ~magent-tools-catalog~ contendo a permissão necessária, embrulhada num bloco ~with-eval-after-load 'magent-tools~.
4. *Habilitação Default:* Assegure que a permissão da ferramenta seja ativada inserindo-a em ~magent-enable-tools~ (dentro de ~with-eval-after-load 'magent-config~).
5. *Warnings do Byte-Compiler:* Forneça forward-declarations ~(defvar magent-tools-catalog)~ e ~(defvar magent-enable-tools)~ para evitar erros de /free-variable/.

Exemplo:
#+begin_src elisp
(defvar magent-tools-catalog)
(defvar magent-enable-tools)

(defvar my-custom-tool
  (gptel-make-tool
   :name "my_tool"
   :function #'my-custom-function
   :description "Faz algo útil"
   :args (list (list :name "arg" :type 'string :description "Exemplo"))
   :category "custom"))

(with-eval-after-load 'magent-tools
  (add-to-list 'magent-tools-catalog
               (list :name "my_tool"
                     :tool my-custom-tool
                     :permission 'my_tool_permission)))

(with-eval-after-load 'magent-config
  (add-to-list 'magent-enable-tools 'my_tool_permission))
#+end_src


* Arquitetura Agêntica Híbrida (Cloud Strategist + Local Driver via magent-cli)

Visão geral da arquitetura de FinOps =\$0.00= com otimização de tokens pagos.

** Topologia Híbrida
- *Cloud Strategist (Modelo Pago):* Atua no nível de planejamento, arquitetura e decomposição de tarefas complexas (ex: Gemini, OpenCode, AGY). Consome o mínimo de tokens pagos.
- *Local Driver (Modelo Local via Colibre / MLX):* Atua no nível de execução física e geração de código local (ex: =qwen3.6-colibri= na porta 8082 na GPU Metal do Mac M2).
- *Bridge Nativo (=magent-cli=):* Invoca deterministicamente as ferramentas nativas do MyEmacs (=sh_smart_edit=, =c_smart_edit=, =elisp_smart_edit=, =magit_*=, =rag_create_doc=).

** Benefícios Empíricos de FinOps
- *Economia de Tokens Pagos:* Redução de até 95% do consumo de API paga ao manter o loop de execuções mecânicas no modelo local.
- *Latência e Desempenho:* Respostas locais ultra-rápidas (~1.0s TTFT no Apple Silicon Metal) com 9.68 GB RSS.
- *Precisão Sintática:* AST e Smart-Edits do MyEmacs garantem 0% de erro sintático com rollback transacional automático.


* Resiliência de FSM, Sentinel e Subagentes

** Resiliência de Subagentes e Cleanup de Timeout
- *Arquivo:* =lisp/custom-magent-subagent.el=
- *Problema:* Subagentes invocados via =spawn_agent= cujas requisições LLM penduravam deixavam jobs orfãos em estado =running= após o expirar do =wait_agent= (120s).
- *Solução Arquitetural:*
  1. *Cleanup no =wait_agent=:* Quando =finish= recebe o status ="timeout"=, aciona =magent-agent-loop-abort= para abortar ativamente o loop filho e transiciona o job para =cancelled= com erro ="Wait timed out"=.
  2. *Watchdog por Job:* Timer configurado no momento do =spawn_agent= que cancela automaticamente após =magent-request-timeout=, garantindo coleta mesmo sem observer ativo.
  3. *Propagação em Cascata:* A FSM do subagente limpa timers e desregistra observadores, evitando vazamento em memória e concorrência no runtime do Emacs.

** Resiliência do Sentinel e Interação com Orquestrador
- *Arquivo:* =lisp/custom-magent-tools.el= e =lisp/custom-magent-commands.el=
- *Sentinel Shield:* Wrapper =condition-case= em =magent-tool-result-require= intercepta exceções primitivas (ex.: =wrong-type-argument=) e encapsula em =magent-tool-result= com status de falha, impedindo a queda do Sentinel do Emacs.
- *Sideband Queue:* Prompts submetidos pelo usuário enquanto o agente gera ou aguarda subagente são enfileirados em =+carlos/magent-sideband-queue= em vez de disparar erros de buffer ocupado.
- *Interrupção Imediata:* Atalho =C-c A i= e menu Transient =+carlos/magent-menu= (=C-c A m=) para aborto determinístico da sessão ativa.


* Ciclo de Vida do Circuit Breaker em Streaming e Tool Use

- *Arquivo:* =lisp/custom-magent-tools.el= (=+carlos/magent-cb-gptel-request-advice=)
- *Natureza Multi-Chamada:* O gptel invoca o callback registrado repetidas vezes:
  1. Chunks parciais de streaming de texto (=stringp response=).
  2. Blocos parciais de raciocínio/pensamento (=reasoning=).
  3. Término do stream de transporte com =(eq response t)=.
  4. Lote de chamadas de ferramenta =(cons 'tool-call pending-calls)= disparado pela FSM do gptel/Magent.
- *Renovação Dinâmica do Watchdog:*
  - A cada chunk intermediário ou emissão de evento válido, o timer de timeout é cancelado e reprogramado, prevenindo abortos indevidos em gerações longas.
  - O Circuit Breaker computa falha estritamente em respostas nulas, status de erro ou detecção de saldo insuficiente.
  - Sucesso é registrado exclusivamente no fim de resposta conclusiva sem ferramentas pendentes.
  - Garante repasse irrestrito de todos os deltas e tool calls para o loop do Magent.
