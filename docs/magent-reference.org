* Overview

Magent is a native Emacs-Lisp AI coding agent framework. It provides a complete
agentic development environment inside Emacs with:

- 15 native tools for filesystem, execution, search, and Emacs state manipulation
- Granular per-agent permissions (allow / ask / deny)
- Project-based ledger sessions (thread → turn → item)
- Skills and capabilities system
- Frontend powered by =agent-shell= via ACP (Agent Control Protocol) in-process adapter
- Transport provided by =gptel-request=

* Installation

Magent is installed via a pin git recipe using Elpaca:

#+BEGIN_SRC elisp
(use-package magent
  :ensure (magent :repo "Jamie-Cui/magent"
                  :ref "50ef707"
                  :files ("lisp/magent*.el" "prompts" "skills" "capabilities"))
  :custom
  (magent-default-agent "build")
  (magent-enable-audit-log t)
  (magent-project-instruction-file-names '("AGENTS.md"))
  (magent-include-reasoning t))

(with-eval-after-load 'magent
  (magent-agent-shell-ensure-config))
#+END_SRC

Dependencies (=yaml=, =acp=, =agent-shell=, =shell-maker=, =cond-let=, =compat=) are resolved automatically by Elpaca.

* Architecture & Transport

Magent operates as an in-process agent framework:

1. **Frontend:** =agent-shell= renders interactive agent UI in buffer =*Magent*=.
2. **Protocol Adapter:** =acp= (Agent Control Protocol) handles asynchronous agent loop communication.
3. **Transport Layer:** Magent uses =gptel-request= under the hood to send LLM requests to any of the backends registered in =custom-ai.el= (Zen Claude, Zen OpenAI, Gemini, Ollama, MLX).

* Streaming Pipeline (Content vs Reasoning) — conhecimento crítico

O adapter de streaming é =magent-llm-gptel--callback= em
=elpaca/builds/magent/magent-llm-gptel.el:756=. Ele classifica cada chunk do
gptel em três vias — e essa distinção é a causa-raiz da maioria dos bugs de
"agente que não responde":

| Via | Handler | O que acontece | Tool call parseia? |
|-----+---------+----------------+--------------------|
| **Content** (=stringp response=) | linhas 760–770: acumula em =:text-chunks= e emite =magent-llm-text-delta-event=; no fim do turn emite =--emit-completed-or-textual-tool-calls= (linha 552) | Texto da resposta final | **SIM** — roda =magent-llm-gptel--parse-dsml-tool-calls= (linha 363) |
| **Reasoning** (=(cons 'reasoning text)=) | linhas 776–793: acumula em =:reasoning-chunks= e emite =magent-llm-reasoning-delta-event= | Raciocínio "pensando alto" do modelo | **NUNCA** — vai direto ao delta-event, sem parser |
| **Tool-call nativo** (=(cons 'tool-call ...)=) | linhas 794–806: normaliza e emite =magent-llm-tool-call-event= | Chamada de função nativa JSON | n/a (já é nativo) |

**Regra de ouro:** *uma tool call escrita no stream de reasoning é
silenciosamente descartada — o magent só executa tool calls vindas do content
(DSML) ou do canal nativo `tool-call`.* O terminal do turn ainda dispara
(linha 807 =eq response t= → =--emit-completed-or-textual-tool-calls=), mas
com o text vazio → resposta vazia. Por isso modelos "pensadores" (Qwen3.5,
DeepSeek-R1) que decidem chamar ferramenta durante o thinking geram turns
mortos.

O FSM de transporte do gptel é =magent-llm-gptel--make-sampling-fsm=
(linha 736): ~INIT→WAIT→TYPE→(TOOL|DONE)~, com pausa em tool calls e resume
explícito do contexto.

* Formato DSML (textual) — o único formato textual parseado

=magent-llm-gptel--parse-dsml-tool-calls= (linha 363) reconhece **apenas** o
envelope textual do Anthropic:

#+BEGIN_SRC xml
<tool_calls>
<invoke name="read_file">
<parameter name="path">/abs/path</parameter>
</invoke>
</tool_calls>
#+END_SRC

NÃO reconhece (foram vistos em logs reais de modelos pequenos sob contexto
pesado):

- =<tool_call><function=read_file><parameter=path>...= (formato Claude-XML
  "legacy" que Qwen3.5-9B às vezes emite);
- envelopes sem espaço após =<invoke= (o parser procura ~"<invoke "~ exato,
  linha 396);
- tags fora de =<tool_calls>=...=</tool_calls>=.

O parse tem limite =magent-llm-gptel--textual-tool-call-max-length=; blocos
maiores são ignorados. Constantes dos tags: =--dsml-tool-calls-open/close=.

* Modos de falha observados (modelos locais) — 2026-08-10

Diagnosticados em sessões reais + reprodução batch contra o servidor MLX
(127.0.0.1:8081). Modelo ativo por padrão: =mlx-community/gemma-4-e2b-it-4bit=
(trocado de =Qwen3.5-9B-MLX-4bit= em 2026-08-10 — ver benchmark abaixo):

1. **Tool call no reasoning (mais grave):** sob contexto pesado (~11.2K
   tokens, 15 tools, AGENTS.md de 22KB) o modelo emite a chamada como
   Claude-XML dentro do thinking → reasoning nunca executa → turn vazio.
2. **SIGPIPE (exit 141):** comando ~find ... | head -50~ — quando o head
   fecha o pipe, o produtor é morto com SIGPIPE; o magent reporta o tool
   result como ~status: failed~, o que entra no histórico e acelera a
   degradação do modelo local (ele "aprende" do erro do próprio turn).
3. **14B timeout:** DeepSeek-R1-Distill-Qwen-14B-4bit não respondeu em
   ~150s (servidor MLX lento; pode precisar de carga do modelo + timeout
   maior).

- **Alternativa de maior raciocínio:** =mlx-community/Qwen3-14B-4bit= pode
  ser usado para tarefas off-line/não interativas (análise de impacto), onde
  37.8s de latência é aceitável.
- **Alternativa compacta (host aa102-006l / Ollama):** =qwen2.5-coder:3b=

- Diretriz 7 (nova): evitar =find | head= → usar =find -maxdepth N= ou

  abordagem por prompt é probabilística — não é uma garantia).

* Loop de Eventos FSM do Magent (Arquitetura & Design de Orquestração)

A FSM do Magent regula de forma assíncrona as iterações cognitivas e chamadas de ferramentas no Emacs sem bloquear o thread principal da interface. Ela gerencia o chaveamento de modelos, tratamento de erros, watchdog e fallback dinâmico baseado no perfil do host ativo.

** Estrutura de Estados da FSM:
- =idle=: Aguardando prompt do usuário.
- =planning=: (Nuvem - Gemini Pro / Sonnet) Produção do plano de roteamento e passos necessários no buffer.
- =thinking=: (Local - DeepSeek R1 / Qwen Coder) Execução do ciclo cognitivo e decisão de qual ferramenta invocar (Thought -> Action -> Observation).
- =tool-executing=: (Emacs) Execução física de ferramentas do catálogo (ex.: snippet_expand, flycheck_errors).
- =verifying=: (Flycheck/LSP) Validação da estabilidade do código alterado. Se houver erros, retorna para =thinking=; se zero erros, vai para =summarizing=.
- =summarizing=: (Nuvem) Geração do relatório final e atualização FinOps para o usuário.

** Tabela de Roteamento de Perfis por Host:
A FSM adapta dinamicamente os backends e modelos do gptel dependendo de onde o Emacs está rodando:

| Função / Estado FSM | MacBook Pro M2 (=agnes.local=) | Estação NixOS/CPU (=aa102-006l=) |
|---------------------+-------------------------------+---------------------------------|
| *Orquestração*      | Local: Gemma 2B (e2b MLX GPU) | Nuvem: Gemini 2.5 Flash (Free)  |
| *Planejamento*      | Nuvem: Claude 3.5 Sonnet      | Nuvem: Gemini 2.5 Pro / Sonnet  |
| *Desenvolvimento*   | Local: Qwen 3.5 9B (MLX GPU)  | Local: Qwen 2.5 Coder 3B (CPU)  |
| *Raciocínio*        | Local: DeepSeek R1 14B (MLX)  | Local: DeepSeek R1 1.5B (CPU)   |
| *Revisão (Audit)*   | Nuvem: Big Pickle (72B)       | Nuvem: Big Pickle (72B)         |

** Mecanismos de Robustez e Resiliência:
1. **Watchdog de Latência:** Um timer de contagem regressiva =+carlos/magent-watchdog-timer= monitora a requisição ativa de desenvolvimento local. Caso o tempo limite (8s no MacBook, 15s na aa102-006l) seja atingido devido ao carregamento de pesos (cold-start) ou lentidão na CPU, a FSM aborta a chamada e faz fallback transparente do turno para a nuvem.
2. **Sanitizador de Reasoning:** Captura e acumula o fluxo do canal =reasoning= do gptel. Se o modelo tentar chamar uma ferramenta em formato de tag (Claude-XML ou DSML) dentro do pensamento, um parser regex extrai a chamada e a envia ao Emacs no canal nativo, contornando a falha nativa do gptel-request de descartar tool calls no reasoning.
3. **Trava de Edição (Semáforo de Buffer):** Impede modificação manual pelo usuário no buffer ativo durante o estado =tool-executing=, garantindo a integridade dos pontos e marcações de cursor.

* Magent Driver Tools (Fase A — Curated in-process tools) — adicionado 2026-08-12

Estes são os utilitários de alto nível implementados para transformar o Magent em um operador de ferramentas e buffers ativos in-process (Tool Operator). Elas são registradas no `magent-tools-catalog` sob o escopo de segurança individual e podem ser estendidas no futuro:

** 1. `flycheck_errors`
- **Nome Técnico:** `flycheck_errors`
- **Handler Elisp:** `+carlos/magent-tool-flycheck-errors`
- **Descrição:** Varre o linter/checker ativo do Flycheck no buffer do caminho especificado em `:path` (ou no buffer atual se `:path` estiver vazio) e retorna um relatório estruturado contendo a lista completa de erros (linha, coluna, nível de severidade, checker responsável e mensagem de erro).
- **Parâmetros:**
  - `:path` (string, opcional): Caminho do arquivo ou buffer vivo para verificação.
  - `:reason` (string, opcional): Razão ou finalidade de checar erros.
- **Formato da Saída (plist):**
  #+begin_src elisp
  (:status "success" :buffer "nome" :file "/caminho/real.el" :total_errors 1 :errors ((:line 42 :column 12 :level "error" :message "void-function X" :checker "emacs-lisp")))
  #+end_src

** 2. `lsp_navigation`
- **Nome Técnico:** `lsp_navigation`
- **Handler Elisp:** `+carlos/magent-tool-lsp-navigation`
- **Descrição:** Usa o backend Xref/Eglot (LSP) ativo no buffer atual para resolver a localização exata de definições ou referências de um símbolo, retornando o nome do arquivo, a linha de ocorrência e uma linha de resumo. É a ferramenta principal para o agente ler assinaturas e evitar a alucinação de nomes de variáveis/funções.
- **Parâmetros:**
  - `:symbol` (string, obrigatório): Nome do símbolo, função ou tipo que se deseja inspecionar.
  - `:action` (string, opcional): `"definition"` (padrão) ou `"references"`.
  - `:reason` (string, opcional): Finalidade da navegação.
- **Formato da Saída (plist):**
  #+begin_src elisp
  (:status "success" :symbol "+carlos/gptel-cache-hit-rate" :action "definition" :total 1 :results ((:summary "defun +carlos/gptel-cache-hit-rate (input cached)" :file "/abs/path/lisp/custom-ai.el" :line 705)))
  #+end_src

** 3. `snippet_expand`
- **Nome Técnico:** `snippet_expand`
- **Handler Elisp:** `+carlos/magent-tool-snippet-expand`
- **Descrição:** Permite listar, inspecionar e fisicamente expandir/inserir templates do Tempel no buffer de edição.
- **Parâmetros:**
  - `:name` (string, opcional): Nome do snippet do Tempel (ex: `"deftest"` ou `"defun"`). Obrigatório se a ação for `inspect` ou `insert`.
  - `:action` (string, opcional): Ação a ser executada. Pode ser `"list"` (padrão se `:name` for nulo), `"inspect"` (retorna a estrutura lisp do template do snippet), ou `"insert"` (expande fisicamente o snippet no buffer corrente sob o cursor do usuário usando `tempel-insert`).
  - `:mode` (string, opcional): Nome de um major-mode específico para filtrar/listar templates (ex: `"emacs-lisp-mode"`).
  - `:reason` (string, opcional): Razão para expandir/inspecionar/inserir o snippet.
- **Formato da Saída (plist):**
  - Para listagem:
    #+begin_src elisp
    (:status "success" :mode "emacs-lisp-mode" :total 12 :snippets ("deftest" "defun" "let" ...))
    #+end_src
  - Para inspeção:
    #+begin_src elisp
    (:status "success" :name "deftest" :template "((p \"Test name: \" name) ...)")
    #+end_src
  - Para inserção física:
    #+begin_src elisp
    (:status "success" :message "Snippet 'deftest' inserido com sucesso no buffer.")
    #+end_src

* Permissions & Audit Logging

** Permission Rules
Permissions are evaluated per agent and per tool. Possible values:
- ~allow~: Tool execution runs automatically without prompt.
- ~ask~: Prompt user for confirmation before executing.
- ~deny~: Block tool execution.

Default security policy for ~build~ agent:
- Read, search, glob, grep: ~allow~
- Write, bash, emacs_eval: ~ask~

** Audit Logging
When ~magent-enable-audit-log~ is ~t~, Magent records all agent decisions, tool invocations, and approvals to JSONL log files under ~magent-session-directory/audit/~.

* Pitfalls & Best Practices

1. **Emacs 30 =defvar= gotcha:** Forward declarations of variables with non-nil defcustom defaults MUST use the bare form ~(defvar X)~ with ~(boundp 'X)~ guards to avoid clobbering runtime defaults with ~nil~.
2. **Use-package `:after`:** With ~use-package-expand-minimally t~, `:after` blocks are ignored during startup. Always wrap package post-configuration in explicit ~(with-eval-after-load 'magent ...)~.
3. **Use `:custom` for options:** Never use global ~setq~ for defcustom variables. Use `:custom` in ~use-package~.
4. **Single Frontend:** Magent uses =agent-shell= as its primary interactive UI. Keep ~C-c i~ (gptel chat) as a lightweight fallback interface.
