** Segurança e Privacidade (Free Tier vs. Pay-per-Use)
- *Aviso de Privacidade:* Na modalidade *Free Tier*, os dados enviados (prompts) e recebidos (completions) podem ser revisados por revisores humanos e utilizados pelo Google para treinar e aprimorar seus modelos.

** Fornecimento das API Keys (Emacs GUI e batch)

As chaves de nuvem (Gemini/OpenCode Zen/OpenAI) vêm do agenix no host
agnes: =/etc/api-keys.sh= (gerado por =modules/system/agenix-env.nix= do
MyMachine) exporta =OPENCODE_ZEN_API_KEY=, =GEMINI_API_KEY= e
=GOOGLE_API_KEY= a partir dos segredos descriptografados em
=/run/agenix/*= (após =darwin-rebuild switch=). O =~/.zshrc= sourcea esse
arquivo, mas o *Emacs GUI (Emacs.app) não herda o ambiente do shell* — sem
as env vars, =gptel--get-api-key= retorna =nil= e qualquer request Gemini
falha com =Wrong type argument: stringp, nil= (causa-raiz dos subagentes
com modelo forte em 2026-08-13).

Por isso =lisp/custom-ai.el= carrega =/etc/api-keys.sh= no boot
(=+carlos/api-keys-file=, defcustom; =+carlos/--source-api-keys-from-file=),
resolvendo a forma agenix =export VAR="$(cat /run/agenix/secret)"= sem
sobrescrever variáveis já definidas no ambiente. Se o arquivo não existir
ou os segredos não estiverem descriptografados, as chaves ficam ausentes
(paridade com o shell, que tem o mesmo guard =if [ -r ... ]=).

*** ACHADO 2026-08-14 — mismatch de caminho agenix no agnes (bug latente)

Durante o diagnóstico do bug "colou o buffer de compilação e o agente não
respondeu" (ver magent-reference.org), descobriu-se que o carregamento de
chaves via config *não funciona no agnes*:

- O script gerado (=/etc/api-keys.sh= → =/etc/static/api-keys.sh= →
  =/nix/store/...-etc-api-keys.sh=) referencia **=/run/agenix/google-api=**
  (e =/run/agenix/openai-api=, =/run/agenix/opencode-zen=).
- O mount real do agenix neste host está em **=/run/agenix.d/1/google-api=**
  (hfs, 0400 root:wheel) — =/run/agenix= **nem existe**:

  #+begin_src sh
  ls /run/agenix                  # No such file or directory
  ls -ld /run/agenix.d /run/agenix.d/1   # drwxr-x--x root wheel
  mount | rg agenix               # /dev/disk4 on /private/var/run/agenix.d
  #+end_src

- Consequência: a guarda =if [ -r /run/agenix/google-api ]= do script falha
  silenciosamente → as chaves **nunca** são carregadas via
  =+carlos/--source-api-keys-from-file=. Em batch headless (sem env do
  shell), =GEMINI_API_KEY=nil= → qualquer request Gemini quebra com
  =stringp nil=. No GUI, o Emacs só funciona se o processo herdar a env var
  de outro canal (ex.: launchd/shell) — não via config.
- *Escopo:* o mismatch está na geração do script (MyMachine,
  =modules/system/agenix-env.nix= usa =config.age.secrets.<nome>.path= que
  resolve para =/run/agenix/<nome>=, enquanto o agenix monta em
  =/run/agenix.d/<uid>/= neste darwin) — **correção pertence ao MyMachine**,
  não ao MyEmacs. Mitigação local imediata: injetar a env var
  (=export GEMINI_API_KEY="$(sudo cat /run/agenix.d/1/google-api)"=), como
  feito no harness de repro.
- *Status:* registrado; ainda não corrigido. Nenhum teste ERT cobre isso
  (é config Nix, fora do escopo do repo).

3. *Local* (MLX no agnes / Ollama nos demais) — apenas quando nuvem

**** NOTA (2026-08-14) — gemma-4-e2b-it é modelo de reasoning: exige max_tokens alto
Por ser de *reasoning*, o gemma gera primeiro um bloco grande de pensamento
e só depois o =content=. O =mlx_lm.server= aplica default de **512
completion tokens** quando a request não traz =max_tokens=; com o gptel
(=gptel-max-tokens=nil) e prompts complexos (ex.: buffer de compilação
colado no Magent), o reasoning consumia todo o orçamento → resposta vazia
(=empty-completion=, "não respondeu"). Fix aplicado em 2026-08-14:
backend "MLX Local" envia =:request-params '(:max_tokens 8192)=. Ver
=magent-reference.org= § "Modos de falha observados", item 5.

* 4. Estratégia Oficial de Roteamento de Modelos por Perfil (Magent D9)

** Decisões Arquiteturais de FinOps e Resiliência (2026-08-22)
Para zerar custos durante o desenvolvimento diário e garantir resiliência contra oscilações de tráfego nos servidores do OpenCode Zen:

1. *Free Tier Primário:* Uso prioritário de modelos 100% gratuitos do OpenCode Zen (=big-pickle=, =nemotron-3.5-lightning-free=, =deepseek-v4-flash-free=) e do Google AI Studio (=gemini-2.5-flash=).
2. *Circuit Breaker Fallback:* Em caso de indisponibilidade ou picos de tráfego no =big-pickle=, o Circuit Breaker da FSM chaveia em milissegundos para o =nemotron-3.5-lightning-free= ou =gemini-2.5-flash= sem interromper o trabalho.
3. *Preservação de Saldo no Google AI Studio:* Saldo remanescente de ~$50 no Google AI Studio alocado com exclusividade para o perfil =planner= em =gemini-2.5-pro= quando a tarefa de arquitetura for de alta complexidade.
4. *Paid Tier Opt-in:* Modelos pagos do OpenCode Zen / Zen Claude (=claude-sonnet-5=, =claude-opus-5=, =gpt-5.6-sol=) são acionados apenas sob demanda explícita (=min_tier='paid'=).
