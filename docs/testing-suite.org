* Visão Geral

O MyEmacs utiliza uma suíte de testes nativa baseada no framework *ERT (Emacs Regression Testing)*. A suíte é executada em modo batch e não possui dependências de pacotes externos para rodar o bootstrap básico, garantindo portabilidade absoluta.

Toda e qualquer alteração feita nas configurações deve passar na validação estrita da suíte antes do deploy.

* Portões de Qualidade Rigorosos

Para manter a estabilidade do editor entre diferentes hosts (agnes, aa102-006l), futuros agentes devem respeitar estritamente três portões de qualidade:

** 1. Prevenção de Erros Ocultos de Lisp
Durante a inicialização interativa, erros em hooks (como =after-init-hook= ou =window-setup-hook=) podem ser recuperados pelo Emacs sem abortar o processo, mas deixando a configuração em estado quebrado.
- *Teste associado:* =myemacs-boot-no-lisp-errors= varre o buffer =*Messages*= por strings como =void-function=, =void-variable= ou =Symbol's value as variable is void=.
- *Regra:* Nenhum erro latente de Lisp deve ser gerado no log durante o bootstrap.

** 2. Prevenção de Warnings de Configuração
Warnings sobre sintaxe obsoleta, pacotes ausentes de autoria própria ou chamadas incorretas abrem o buffer =*Warnings*= e atrapalham o fluxo de trabalho.
- *Teste associado:* =myemacs-boot-no-custom-warnings= garante que nenhum aviso vindo de arquivos com prefixo =custom-= ou funções =+carlos/= seja jogado no buffer de warnings.
- *Regra:* Avisos gerados por configurações locais causam a falha imediata da suíte.

** 3. Validação Dinâmica contra Colisões de Atalhos
O Emacs possui um sistema de prioridade de keymaps onde major modes ou minor modes locais podem obscurecer e sobrescrever comandos globais de forma indesejada.
- *Teste associado:* =myemacs-kbd-no-collisions= cria buffers de teste, ativa os principais major modes (=org-mode=, =dired-mode=, =c-mode=, =emacs-lisp-mode=) e usa =key-binding= para garantir que as teclas globais críticas (como =C-c g= para Magit, =C-c i= para gptel e atalhos de IA/Magent) resolvam para os comandos esperados sem sofrer colisões locais.
- *Regra:* Atalhos globais essenciais devem ser funcionais e consistentes em qualquer buffer do editor.

* Como Executar as Validações

O =Justfile= encapsula o fluxo de controle de qualidade:

#+begin_src bash
# 1. Rodar a verificação de carregamento rápido
just check

# 2. Executar compilação de byte-code (trata warnings como erros críticos)
just compile

# 3. Rodar a suíte ERT batch local
just test-batch

# 4. Executar o fluxo completo de qualidade (CI/CD nativo)
just test-all  # Roda compile + checkdoc + test-batch
#+end_src

 * Diretrizes para Evolução da Suíte

Ao adicionar novos recursos ou consertar bugs, siga as regras:
1. *Bugs de Inicialização:* Cada bug resolvido (ex: `void-variable` ou `void-function`) deve ganhar uma asserção específica no =boot-test.el= ou =ai-test.el=.
2. *Novos Atalhos:* Se adicionar um novo atalho global em =custom-keybindings.el=, declare-o na lista =critical-bindings= do teste =myemacs-kbd-no-collisions= em =tests/keybindings-test.el= para protegê-lo contra futuras regressões ou colisões em major modes.
3. *Isolamento de Testes:* Testes de rede (Live APIs) devem conter a tag =:tags '(ai network)= e a macro =(skip-unless (getenv "EMACS_TEST_NETWORK"))= para evitar que falhas de conexão ou falta de chaves quebrem a suíte de testes offline local.

 * Descobertas de Runtime para Mocks (2026-08-13)

Ao escrever testes que mockam funções do gptel/magent, lembre:

1. *Accessors de =cl-defstruct= são INLINED pelo byte-compiler* quando o struct está
   carregado no compile-time — mock de function-cell com =cl-letf= no
   =symbol-function= é *inócuo*: a chamada é expandida para
   =(aref obj slot)= + tipo-check, ignorando o mock. Exemplos vistos:
   =gptel-backend-models=, =gptel-backend-host=, =gptel-backend-protocol=,
   =magent-thread-turn-usage=, =magent-agent-info-name=.
   - *Contorno:* mockar a função que *retorna* o struct (=gptel-get-backend= é
     função normal e mockável) ou injetar os valores como argumento opcional
     das funções sob teste (ex.: `backends`/`local-models` de
     =+carlos/magnet-model-menu-entries=), ou testar a decisão pura (ex.:
     =+carlos/magent-compaction-decision=) em vez do caminho que toca o accessor.
2. *Sem sessão/turno no batch:* =magent-runtime-session-current= e
   =magent-thread-find-turn= retornam nil em batch sem sessão ativa — testes de
   medição de tokens devem garantir zero-safe (=+carlos/magent-turn-tokens=
   retorna 0).
3. *`--init-directory` + `--batch` não carrega =early-init.el=* neste Emacs 30.2
   — =load-prefer-newer-source= fica *void* e um =.elc= stale pode prevalecer
   sobre o =.el= novo ("Source file ... newer than byte-compiled file; using
   older file"). Rode =just rebuild= antes de testar se suspeitar de objeto velho.
4. *=when-let*= com elemento =(fboundp 'X)= vira *binding* (var =fboundp= = símbolo),
   NÃO condição — use bindings nomeados (=(has-get (fboundp 'X)) ...=).
5. *=`push=` em =(alist-get k alist ...)= adiciona a entrada NO FRENTE* do alist
   quando a chave é nova (ordem de inserção, não de tier) — ordene explicitamente
   (ex.: rank de tier) ou use ordem estável.
