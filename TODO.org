* Contexto de Arquitetura Oficial do Magent (Referência RAG)

Síntese da documentação oficial do repositório Magent (=docs/AGENT_JOBS.org=, =docs/AGENT_WORKFLOW.org=, =docs/ONBOARDING.org=):

- *Modelo de Subagentes (AGENT_JOBS.org):* Jobs duráveis com a struct =magent-agent-job= (=queued=, =running=, =waiting=, =completed=, =failed=, =closed=, =cancelled=). O =wait_agent= assina observadores de transição com deadline timer (sem polling). Herança de contexto delimitada por =magent-child-agent-max-depth= (padrão 1 nível).
- *Ledger & State Machine (AGENT_WORKFLOW.org):* Hierarquia Codex =thread -> turn -> item=. Turno gerenciado em =magent-ledger.el=. Itens de ferramenta unificados (=tool-call= e =tool-output= no mesmo registro por =call-id=). Persistência dupla via =Snapshot= (restauração rápida de thread) + =Journal= (log append-only).
- *Camadas de Arquitetura (ONBOARDING.org):* 7 camadas. Camada 2 (Sessão & Ledger), Camada 3 (Agentes e Permissões =allow=/=deny=/=ask=), Camada 4 (15 ferramentas nativas em =magent-tools.el= + aprovações em =magent-approval.el=), Camada 5 (Loop Magent e transport fino =gptel-request= em =magent-llm-gptel.el=), Camada 6 (Frontend =agent-shell= + protocolo ACP em =magent-acp.el=).

## 2. Buscador AST Tree-Sitter (`magent-tool-treesit-query`)

### Funcionalidades
- Buscar referências, callers e definições de funções/classes no projeto inteiro utilizando o motor embutido `tree-sitter`.
- Suportar consultas nativas do `treesit` usando s-expressions ou strings de queries.
- Retornar uma estrutura limpa com caminhos de arquivo, números de linha e o código (nós AST) formatado.
- Funcionar independentemente de LSPs pesados (eglot/lsp-mode), usando puramente a árvore sintática local.

### Domínio e Arquivo
- **Arquivo Lisp:** `lisp/custom-magent-tool-ast.el` (domínio voltado a análise estática e introspecção sintática de código).
- **Função Principal:** `+carlos/magent-tool-treesit-query`.

### Passos de Implementação
1. Criar o arquivo `lisp/custom-magent-tool-ast.el` com o header canônico.
2. Implementar `+carlos/magent-tool-treesit-query` aceitando a linguagem alvo, a query (string) e opcionalmente um escopo (diretório/arquivo ou projeto via `project-current`).
3. Criar uma rotina para iterar rapidamente sobre os arquivos relevantes (filtrados por extensão), ler o conteúdo (com ou sem carregar buffers), e fazer o parse via `treesit-parse-string`.
4. Executar `treesit-query-capture` para extrair os nós que correspondem à busca.
5. Formatar a saída (combinando `treesit-node-text` e convertendo `treesit-node-start` para linha/coluna).
6. Tratar o caso de ausência da gramática requerida (`treesit-language-available-p`) informando um erro tratável ao agente.
7. Registrar a ferramenta na FSM.
8. Documentar o comportamento em `docs/magent-reference.org` utilizando a tool `rag_create_doc`.

Se você rodar o MLX via terminal (python -m mlx_lm.server) ou o Ollama/LM Studio localmente, você pode injetar o schema desta forma.
