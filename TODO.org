* Contexto de Arquitetura Oficial do Magent (Referência RAG)

Síntese da documentação oficial do repositório Magent (=docs/AGENT_JOBS.org=, =docs/AGENT_WORKFLOW.org=, =docs/ONBOARDING.org=):

- *Modelo de Subagentes (AGENT_JOBS.org):* Jobs duráveis com a struct =magent-agent-job= (=queued=, =running=, =waiting=, =completed=, =failed=, =closed=, =cancelled=). O =wait_agent= assina observadores de transição com deadline timer (sem polling). Herança de contexto delimitada por =magent-child-agent-max-depth= (padrão 1 nível).
- *Ledger & State Machine (AGENT_WORKFLOW.org):* Hierarquia Codex =thread -> turn -> item=. Turno gerenciado em =magent-ledger.el=. Itens de ferramenta unificados (=tool-call= e =tool-output= no mesmo registro por =call-id=). Persistência dupla via =Snapshot= (restauração rápida de thread) + =Journal= (log append-only).
- *Camadas de Arquitetura (ONBOARDING.org):* 7 camadas. Camada 2 (Sessão & Ledger), Camada 3 (Agentes e Permissões =allow=/=deny=/=ask=), Camada 4 (15 ferramentas nativas em =magent-tools.el= + aprovações em =magent-approval.el=), Camada 5 (Loop Magent e transport fino =gptel-request= em =magent-llm-gptel.el=), Camada 6 (Frontend =agent-shell= + protocolo ACP em =magent-acp.el=).

** TODO Componente 5: Servidor de Ferramentas (Tool Server Bridge)
A inteligência da CLI =agy= externa precisa consumir as ferramentas Lisp nativas do Emacs.
O Proxy resolve isso agindo como ponte de inversão de controle.

*** Fluxo FSM Tool Interceptor
1. *Discovery*: O proxy expõe as ferramentas nativas (magit, org_smart_edit, elisp_smart_edit, dape) como array de =tools= na API OpenAI-compatible enviada ao Upstream.
2. *Interceptação*: Quando a API retorna =tool_calls=, o FSM intercepta.
3. *Execução Bridge*: O FSM usa =bin/magent-cli= (rodando =emacs --batch -l init.el=) para executar a função de forma idêntica à versão nativa no Emacs.
4. *Resolução*: O FSM do Proxy retorna os =tool_results= ao LLM transparente para o cliente =agy=.
