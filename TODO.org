* Plano Diretor — Ambição e Pipeline de Execução

** A Ambição (north star)

#+BEGIN_QUOTE
Magent/gptel como driver do Emacs: o agente opera o editor como um parceiro de
pareamento em vez de cuspir código para revisão. Em vez de escrever uma função
inteira, o modelo expande um tempel snippet e preenche apenas as lacunas —
usando o buffer vivo, flycheck/LSP para validar e corrigir em loop, e xref para
resolver símbolos reais (sem alucinar nomes).
#+END_QUOTE

Exemplo concreto (alvo): "adiciona um helper para X" → =lsp_navigation= resolve
o símbolo → =snippet_expand= insere o esqueleto em point → o modelo preenche só
os campos → =flycheck_errors= valida → corrige até zero erros. Nada de bloco
inteiro colado.

** TODO D5. Context Sharing Dinâmico para Subagentes
    :PROPERTIES:
    :CREATED: 2026-08-18
    :ASSIGNEE: coder
    :STATUS: backlog
    :END:

*Problema:* subagentes recebem apenas o prompt raw do orquestrador. Não
recebem: histórico de conversa do pai, arquivos lidos/editados, decisões
tomadas na sessão, nem o estado acumulado do orquestrador. Isso obriga o
orquestrador a repetir contexto no prompt (gastando tokens) ou o subagente
trabalha às cegas.

*Solução:* coletar contexto dinâmico do orquestrador (arquivos tocados,
ações recentes, estado do projeto) e injetar automaticamente no prompt
do subagente antes de delegar. Abordagem: enrich do =user-prompt= no
=+carlos/magent-subagent-apply-profile= (não modifica upstream).

*** D5.1 — Context Collector (coletor de estado do orquestrador)
    :PROPERTIES:
    :ASSIGNEE: coder
    :END:

Em =custom-magent-subagent.el=:

1. Nova variável =+carlos/magent-orchestrator-context= (alist):
   - =:files-read= — lista de arquivos lidos via =read_file= (últimos 5).
   - =:files-edited= — lista de arquivos editados (últimos 5).
   - =:recent-actions= — resumo das últimas 3 ações (tool + resultado).
   - =:project-state= — branch, arquivos modificados (via =git status=).
   - =:task-context= — understandsão atual da tarefa (extraída do prompt).

2. Função =+carlos/magent-collect-orchestrator-context=:
   - Le =magent-tools--request-context= (dinâmico durante execução).
   - Extrai =magent-session-thread= → =magent-thread-turn-items= →
     itens de turno com tool-call-start/end.
   - Filtra por tool name (=read_file=, =edit_file=, =write_file=,
     =bash=) e extrai args + result summary.
   - Armazena em =+carlos/magent-orchestrator-context=.

3. Hook no =turn-end-sink= (ou advice em =magent-agent-loop-end-turn=)
   para atualizar o contexto ao final de cada turno.

*** D5.2 — Context Formatter (formatação do contexto)
    :PROPERTIES:
    :ASSIGNEE: coder
    :END:

Em =custom-magent-subagent.el=:

1. Função =+carlos/magent-format-orchestrator-context=:
   - Recebe o alist de contexto.
   - Formata como bloco compacto para prepender ao prompt:
     #+BEGIN_EXAMPLE
     [Orchestrator Context]
     Files read: lisp/custom-magent-fsm.el, lisp/custom-magent-tools.el
     Files edited: lisp/custom-magent-fsm.el
     Recent: spawn_agent(explore) → completed, read_file(TODO.org) → 340 lines
     Project: branch main, 2 modified files
     Task: implement context sharing for subagents
     [/Orchestrator Context]
     #+END_EXAMPLE
   - Cap: max 500 chars para não consumir tokens desnecessários.
   - Se contexto vazio, retorna nil (não injeta nada).

2. Função =+carlos/magent-build-subagent-prompt=:
   - Recebe =original-prompt= e =context-block=.
   - Se context-block não é nil, prepend ao prompt.
   - Retorna prompt enriquecido.

*Testes ERT:*

*** D5.4 — Testes de integração e edge cases

*Cenários a testar:*
1. Orquestrador leu 3 arquivos e editou 1 → subagente recebe contexto
   com os 3 arquivos lidos e o editado.
2. Orquestrador sem nenhuma tool call → contexto vazio, prompt preservado.
3. Sessão com 10+ arquivos tocados → apenas últimos 5 no contexto.

5. =context-sharing-enabled= nil → prompt passa sem modificação.
6. Múltiplos subagentes na mesma sessão → cada um recebe o contexto
   atualizado do orquestrador.

** TODO D11. Pipeline de Documentação via Chat (Logic Extractor + Tech-Writer)
    :PROPERTIES:
    :CREATED: 2026-08-18
    :ASSIGNEE: planner
    :STATUS: backlog
    :TAGS: :magent:tools:
    :END:

*Contexto:* orquestrador deve reconhecer intenção do usuário ("explica o que X
faz", "documenta esse módulo", "analisa as regras de negócio") e acionar
pipeline de dois estágios automaticamente (sem keybinding).

*Pipeline:*
1. Orquestrador lê arquivo (=read_file=);
2. =spawn_agent('logic-extractor', código)= → extrai JSON com regras de negócio;
3. =wait_agent= → recebe JSON;
4. =spawn_agent('tech-writer', JSON + instrução Org)= → converte para =.org=;
5. =wait_agent= → recebe documentação;
6. Sintetiza ≤3 bullets para o usuário; oferece salvar =.org= se solicitado.

*Abordagem:*
- Novo perfil =logic-extractor= em =+carlos/magent-subagent-profiles=
  (:min-tier "free") — analista de código, não refatora, não testa,
  apenas traduz código imperativo → regras declarativas (JSON).
- Instrução dedicada =+carlos/magent-logic-extractor-instruction=:
  schema JSON com =modulo=, =proposito=, =pre_condicoes=, =regras=,
  =side_effects=.
- Instrução =+carlos/magent-tech-writer-instruction= ajustada para
  receber JSON e produzir =.org= válido (=* Modulo= → =** Propósito= →
  =** Regras= → =** Efeitos Colaterais=).
- Regra 12 em =+carlos/magent-system-directives=:
  "When user asks to 'document', 'explain what this does', or 'analyze
  business logic': spawn logic-extractor, wait, spawn tech-writer, wait,
  synthesize ≤3 bullets."
- Sem keybinding — ativação 100% via chat natural.

*Critério de saída:* =just compile= zero-warning; 3 testes ERT novos
(perfil logic-extractor registrado, instruções não-vazias, regra 12
presente nas directives); =just test-all= verde; teste interativo com
Flash documentando um arquivo =.el= existente.

*Arquivos:* =lisp/custom-magent-subagent.el=, =lisp/custom-magent-tools.el=,
=tests/magent-team-test.el=, =docs/magent-reference.org=.
