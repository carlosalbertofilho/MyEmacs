* Plano Diretor — Ambição e Pipeline de Execução

** A Ambição (north star)

#+BEGIN_QUOTE
Magent/gptel como driver do Emacs: o agente opera o editor como um parceiro de
pareamento em vez de cuspir código para revisão. Em vez de escrever uma função
inteira, o modelo expande um tempel snippet e preenche apenas as lacunas —
usando o buffer vivo, flycheck/LSP para validar e corrigir em loop, e xref para
resolver símbolos reais (sem alucinar nomes).
#+END_QUOTE

Exemplo concreto (alvo): "adiciona um helper para X" → =lsp_navigation= resolve
o símbolo → =snippet_expand= insere o esqueleto em point → o modelo preenche só
os campos → =flycheck_errors= valida → corrige até zero erros. Nada de bloco
inteiro colado.

*** Fase E1 — Subagent Result Collector (monitor de conclusão)
    :PROPERTIES:
    :ASSIGNEE: coder
    :STATUS: backlog
    :END:

*Problema:* quando o orquestrador termina o turno sem chamar =wait_agent=
(modelo local viola a directiva 5), o job do subagente continua assíncrono.
A FSM entra em =subagent-waiting= mas não há mecanismo para coletar o
resultado quando o subagente completa.

*Solução:* criar um collector que monitora jobs pendentes e coleta resultados.

Em =custom-magent-fsm.el=:
1. Nova variável =+carlos/magent-fsm-pending-results= (alist job-id → result-text).
2. Função =+carlos/magent-fsm-collect-completed-jobs=:
   - Itera =+carlos/magent-fsm-subagent-jobs= (cache da FSM).
   - Para cada job com status =completed=, extrai =magent-agent-job-result=
     e armazena em =+carlos/magent-fsm-pending-results=.
   - Remove job da lista de pending (status terminal não é mais "pending").
3. Registrar observer em cada job via =magent-agent-job-add-observer= quando
   a FSM entra em =subagent-waiting= (no =turn-end-sink=).
4. Observer callback: quando status =completed= ou =failed=, coleta resultado
   e armazena em =+carlos/magent-fsm-pending-results=.

*Testes ERT:*
- =myemacs-magent-fsm-collect-completed-jobs-extracts-result=
- =myemacs-magent-fsm-collect-completed-jobs-removes-from-pending=
- =myemacs-magent-fsm-observer-callback-stores-result=

*** Fase E2 — Deferred Result Injection (injeção pós-turno)
    :PROPERTIES:
    :ASSIGNEE: coder
    :STATUS: backlog
    :END:

*Problema:* mesmo com o resultado coletado, não há mecanismo para injetá-lo
no contexto do orquestrador após o turno ter terminado.

*Solução:* quando a FSM detecta que há resultados pendentes no
=turn-start-sink=, injeta o resultado como mensagem de sistema antes de
iniciar o próximo turno.

Em =custom-magent-fsm.el=:
1. Função =+carlos/magent-fsm-inject-pending-results=:
   - Verifica =+carlos/magent-fsm-pending-results=.
   - Para cada resultado, formata como mensagem de contexto:
     =[Subagent <agent-name> completed]: <result-text>=
   - Retorna a lista de mensagens para injetar.
2. Modificar =+carlos/magent-fsm-turn-start-sink=:
   - Antes de transicionar para =thinking= ou =subagent-running=,
     chamar =+carlos/magent-fsm-inject-pending-results=.
   - Se houver resultados, adicionar ao prompt do orquestrador via
     =magent-request-context= ou callback de UI.
3. Limpar =+carlos/magent-fsm-pending-results= após injeção.

*Testes ERT:*
- =myemacs-magent-fsm-inject-pending-results-formats-correctly=
- =myemacs-magent-fsm-inject-pending-results-clears-after-injection=
- =myemacs-magent-fsm-turn-start-injects-before-transition=

*** Fase E3 — Orchestrator Resume (retomada do turno)
    :PROPERTIES:
    :ASSIGNEE: coder
    :STATUS: backlog
    :END:

*Problema:* injetar a mensagem não basta — o orquestrador precisa ser
retomado para processar o resultado do subagente.

*Solução:* quando há resultados injetados, o =turn-start-sink= deve
sinalizar que o próximo turno deve começar com contexto enriquecido.

Em =custom-magent-fsm.el=:
1. Variável =+carlos/magent-fsm-resume-with-context= (flag booleano).
2. Quando =+carlos/magent-fsm-inject-pending-results= retorna resultados
   não-vazios, setar flag =t=.
3. Em =+carlos/magent-fsm-turn-start-sink=, se flag está ativa:
   - Transicionar para =thinking= (não =subagent-running=).
   - A flag sinaliza para o handler de UI que o turno deve incluir
     o contexto do subagente como mensagem de sistema.
4. Reset da flag após uso.

*Integração com UI:*
- O =magent-agent-shell= (ou o handler de turno) verifica a flag e
  adiciona as mensagens pendentes ao prompt antes de enviar ao LLM.
- Alternativa: usar =magent-request-context= para injetar contexto
  diretamente no request.

*Testes ERT:*
- =myemacs-magent-fsm-resume-flag-set-on-pending-results=
- =myemacs-magent-fsm-resume-flag-cleared-after-use=
- =myemacs-magent-fsm-turn-start-uses-resume-context=

*Cenários a testar:*

** TODO D11. Pipeline de Documentação via Chat (Logic Extractor + Tech-Writer)
    :PROPERTIES:
    :CREATED: 2026-08-18
    :ASSIGNEE: planner
    :STATUS: backlog
    :TAGS: :magent:tools:
    :END:

*Contexto:* orquestrador deve reconhecer intenção do usuário ("explica o que X
faz", "documenta esse módulo", "analisa as regras de negócio") e acionar
pipeline de dois estágios automaticamente (sem keybinding).

*Pipeline:*
1. Orquestrador lê arquivo (=read_file=);
2. =spawn_agent('logic-extractor', código)= → extrai JSON com regras de negócio;
3. =wait_agent= → recebe JSON;
4. =spawn_agent('tech-writer', JSON + instrução Org)= → converte para =.org=;
5. =wait_agent= → recebe documentação;
6. Sintetiza ≤3 bullets para o usuário; oferece salvar =.org= se solicitado.

*Abordagem:*
- Novo perfil =logic-extractor= em =+carlos/magent-subagent-profiles=
  (:min-tier "free") — analista de código, não refatora, não testa,
  apenas traduz código imperativo → regras declarativas (JSON).
- Instrução dedicada =+carlos/magent-logic-extractor-instruction=:
  schema JSON com =modulo=, =proposito=, =pre_condicoes=, =regras=,
  =side_effects=.
- Instrução =+carlos/magent-tech-writer-instruction= ajustada para
  receber JSON e produzir =.org= válido (=* Modulo= → =** Propósito= →
  =** Regras= → =** Efeitos Colaterais=).
- Regra 12 em =+carlos/magent-system-directives=:
  "When user asks to 'document', 'explain what this does', or 'analyze
  business logic': spawn logic-extractor, wait, spawn tech-writer, wait,
  synthesize ≤3 bullets."
- Sem keybinding — ativação 100% via chat natural.

*Critério de saída:* =just compile= zero-warning; 3 testes ERT novos
(perfil logic-extractor registrado, instruções não-vazias, regra 12
presente nas directives); =just test-all= verde; teste interativo com
 Flash documentando um arquivo =.el= existente.
