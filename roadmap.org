** 2026-08-06 — Suíte de testes ERT (tests/) e política de regressão

*** Feito
- **Decisão ERT vs Buttercup:** ERT (nativo, zero dependência, roda o boot completo e dá exit code via `ert-run-tests-batch-and-exit`). Buttercup (BDD de terceiros) exigiria instalação via elpaca no ambiente de teste e não cobre "config carrega inteira" de forma natural.
- **Infra:** `tests/load-tests.el` (loader dos `tests/*-test.el` após o init.el) + targets no Justfile: `test-batch`, `test-ai` (selector `myemacs-ai`), `test-network` (opt-in `EMACS_TEST_NETWORK=1`), `test-all` (= compile + checkdoc + test-batch). `check-all` agora inclui `test-all`. Ambiente autoritativo = `~/.config/emacs-vanilla` (via variável `EMACS_TEST_DIR`).
- **Arquivos:** `tests/boot-test.el`, `keybindings-test.el`, `ai-test.el`, `ai-network-test.el` (skip-unless rede), `files-test.el`, `term-test.el` (vterm skip-unless módulo nativo), `git-test.el`, `org-test.el`, `dashboard-test.el`. **54 testes, 0 falhas, 6 skipped** no repo.
- **Bugs reais descobertos pela suíte (corrigidos):**
  - `C-c i` (gptel) sombreado por consult-imenu (use-package `:bind` de pacote deferido reaplica o bind depois) → consult-imenu movido para `M-s i` (mesmo padrão do `C-c h`/`C-c /`).
  - `+carlos/dashboard-open`/`-refresh` declarados e bindados em `C-c d d`/`C-c d r` mas **nunca definidos** (void-function) → wrappers de `dashboard-open`/`dashboard-refresh-buffer`.
  - `git-commit` `C-c C-g` via hook (só aplicava em buffer real; não verificável em batch) → `define-key` direto no `git-commit-mode-map` via `with-eval-after-load 'git-commit`.
- **Ambiente:** removidos `.elc` stale do repo (usavam o código antigo do `defvar nil` bugado); rebuild do build do gptel no repo (faltava `gptel-autoloads.el` → "Config Error gptel: void-function gptel-make-openai").
- **AGENTS.md:** seção "Testing (ERT Suite)" com como rodar/adicionar testes, regras (rede opt-in, `skip-unless`, `--eval` só avalia a 1ª forma) e tabela de bugs resolvidos reescrita.

** 2026-08-06 — Fix: void-variable no runtime (gotcha `defvar` do Emacs 30)

*** Feito
- **Sintoma (teste interativo):** `if: Symbol's value as variable is void: gptel-agent-dirs` ao chamar `C-c I` (+carlos/gptel-agent-run); `C-c C-g` undefined fora do buffer de commit.
- **Causa raiz:** Emacs 30 mudou o `defvar`: `(defvar X)` sem INITVALUE NÃO liga mais a variável — deixa-a **void** (só marca special). As forward declarations peladas não criavam binding → qualquer leitura antes do pacote dono carregar era `void-variable`.
- **Correções:**
  - =custom-ai.el=: forward declarations com valor `nil` onde o default não importa (=gptel-backend=, =gptel-model=); forma PELADA + guarda `unless (boundp 'X) (setq X nil)` para =gptel-agent-dirs= (default do defcustom aponta para o diretório de agentes embutido do gptel-agent) e =gptel-directives= (4 diretivas padrão do gptel) — `nil` clobberaria esses defaults.
  - =custom-term.el=, =custom-files.el=, =custom-writing.el=: `(defvar X)` peladas → `(defvar X nil)` onde seguras (sem default não-nil em jogo).
  - **=use-package :after= ignorado:** com `use-package-expand-minimally t` (init.el), `:after gptel` não gera trigger — gptel-agent nunca carregava com o gptel. Troca por `:ensure t` + `with-eval-after-load 'gptel` (mesmo mecanismo das personas, que funcionava) com `require 'gptel-agent` + `gptel-agent-update`.
  - **=custom-keybindings.el=:** `C-c C-g` global → `+carlos/gptel-generate-commit-message` (antes só existia no buffer de commit); `declare-function` p/ dashboard e project-root.
- **Validação:** backends 5/5 PONG; agentes (researcher/introspector/gptel-plan/gptel-agent/executor) e presets (gptel-default/gptel-agent/gptel-plan) registrados; diretivas = 4 padrão + 3 42; dirs = embutido + global + projeto; `just compile` 16/16 zero warnings; checkdoc OK.
- Lição registrada em =AGENTS.md= (regras p/ `defvar` no Emacs 30).
